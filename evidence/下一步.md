# 历史：CMP 40HX 解锁 — 最终状态 (2026-09-11 11:2x) — 算力 + Gen2 两全达成 ✅

## 结论
用 BardKing-CN 的 **CMP40HX-Unlock-OnlyEFI v0.1.1** 实现两全（此前厂商工具在本机只能二选一）：
- **算力: 满血** — `SS0=0x88888888 SS1=0x00000008`（EFI 每次开机解锁）
- **PCIe: 物理 Gen2 x16** — helper 现场读 `GPU LNKSTA=0x1102` / `ROOT LNKSTA=0xF102`，`PASS: physical Gen2 x16 reached`，退出码 0
- 两者在**同一次运行**里同时成立，且**全程没有复位显卡**（新方案的机制就是不复位）→ 这正是原来解不开的死结

## 机制（与原厂商工具的区别）
| 阶段 | 厂商工具 | OnlyEFI 方案 |
|---|---|---|
| EFI | 解锁 + 写 TLS + **EFI 内重训** | 解锁 + 4 个 TU106 Gen2 策略寄存器 RMW + Root TLS=2，**跳过 EFI 重训** |
| Windows | 登录任务重训；失败 → Link Disable + **PnP 复位显卡**(清算力) | 驱动 bind 后只恢复 2 个被驱动改写的寄存器 + Root Retrain SET_ONLY（**不写 TLS/不复位**）|
实测结果：helper 守卫要求 `SS0=0x88888888` 才动手，恢复 `LINK_CONFIG_0 800C5800→80085800`、`PRIV_MISC_1 E0B40D00→E0B42D00`，
第 2 次 Root Retrain 落地 → 物理 Gen2 x16；复跑报 `already physical Gen2 x16`（链路粘住）。
nvidia-smi 仍显示 `gen.current=1` 是驱动空闲降速视图，**以寄存器为准**。

## 复现与踩坑记录 (2026-09-11 下午)
1. 15:35 那次开机 Gen2 没起来 → 查 `C:\ProgramData\CMP40HXGen2\windows\logs\last.log`:
   `[SC] StartService: OpenService 失败 1060` + `FATAL: ThrottleStop service did not start` (exit 30)。
   原因: 火绒在 11:28 把两个 BYOVD 驱动 .sys 隔离、并把服务一起删了（Quarantine 目录里多一个 50232 字节的无扩展名文件）。
   EFI 那边没问题（`gen.max=2`、`TLS=2` 都在），缺的就是 Windows 侧那次"落地"。
2. 修法（已落地）: 任务 `CMP40HX Gen2 PostBind` 指向自写包装 `RunPostBind.cmd`：
   每轮自愈驱动（4 个普通源 + **ESP 兜底源 `\EFI\40HX\drv\`**）→ `sc create` 重建服务 → 跑厂商 `AutoRetrain.cmd` → 失败重试 3 次（间隔 15s）。
   破坏性测试（删服务 + 删驱动 + 把普通源改名藏起）→ 仍 `exit 0` / `PASS`。日志 `...\windows\logs\postbind.log`。
3. nvidia-smi 判据坑: `pcie.link.gen.current` 即使 40HX 满载 100% 也可能报 1（动态降速 + 纯计算不产生 PCIe 流量）。
   实测同时刻 `release\OpenCL.exe` 基准明确标注 `(Gen2 x16)`、send 5.83 GB/s / 双向 6.16 GB/s、FP32 8.329 TFLOPs/s（算力也在）。
   → **判 Gen2 只看寄存器 LNKSTA 或带宽工具，别用 nvidia-smi。**
