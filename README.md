## 这个包做三件事

CMP 40HX 是矿卡：出厂被人为压了算力（寄存器 SS0 锁住），PCIe 链路压到 Gen1，BAR1 也被压成 64 MiB。
2026-10-14 起这个包一共做三件事（前两件默认就装，第三件要你自己选）：

1. **解锁算力**（SS0 = 0x88888888，FP32 从 约 1.9 TFLOPs 回到 约 8.35 TFLOPs）
2. **把 PCIe 拉到 Gen2 x16**（双向量测带宽 约 6 GB/s，Gen1 只有 约 3.4 GB/s）
3. **ReBAR 8 GiB**（BAR1 从 64 MiB 变 8 GiB，显存整块映射；只在开机固件阶段能开 —— 选做，见下面专节）

前两件**每次开机自动保持**（开机时固件写寄存器 + 开机任务重训链路）；第 3 件是把解锁固件换成带 ReBAR 的版本并设为第一启动项，同样每次开机自动生效，你不用天天点。

> **锁态卡（算力被固件拒签）也想只把 Gen2 拉起来**：双击 `一键解锁40HX.bat` 选 **3**（不动 ESP/固件启动项、不解算力）。

## 为什么用它：ACE 不用关（本包最核心的差别）

CMP 40HX 的算力限制是一个**显卡寄存器锁**。解它的方式有两种，代价完全不同：

| 项 | **本包** | 我们见过的其它做法的差别 |
|---|---|---|
| 算力解锁发生在**哪一层** | **开机固件阶段（UEFI，进 Windows 之前）** —— `\EFI\40HX\40HXUNLK.EFI` 每次开机把 `SS0`/`SS1` 写回解锁值 | 多数方案在 **Windows 运行期**用内核驱动去改寄存器 |
| 腾讯 ACE / ACE-BOOT | **不用关、不用杀 `ACE-Tray.exe`、不用卸载反作弊**，游戏照常跑 | 那类做法要么得先停反作弊，要么直接被 ACE 拦掉（驱动装载被拒） |
| 驱动 / 系统更新之后 | 不受影响（每次开机固件重写一遍） | 常因驱动重载而失效，要回去重跑工具 † |
| 是否需要联网 / 厂商安装器 | 不需要 | 常需要 † |
| 卸载 | 双击 `一键卸载.cmd`，下次开机回原生 | 常留残留服务 / 驱动 † |

为什么 ACE 拦不住：

- **ACE（含 ACE-BOOT）从"Windows 映像加载"阶段开始执法**，它按名单拦的是**在 Windows 里被加载的驱动**。
  我们的解锁固件跑在它启动**之前**，写完寄存器就交棒给 `bootmgfw.efi` —— ACE 醒来时锁已经开了，它看不到那一步。
- **2026-09-22 实测（`docs/06-ace-boot.md` §1）**：ACE 当时拦的是老方案要用的 `ThrottleStop.sys`，`sc start` 返回**错误 31**（该文档**第 46 行**）；
  同一份记录紧接着写的就是「3. **同一次开机 ESP `40hx_log.txt` 里仍然有** `*** UNLOCKED (SS0=0x88888888 SS1=0x8) ***`」（**第 28–33 行**）—— 算力与 ACE 无关。
- **Gen2 也不是靠反作弊让步换来的**：Windows 侧用 `inpoutx64.sys` 直写 GPU BAR0 + `WinRing0x64.sys` 写 PCI 配置空间，
  全程**不停止 ACE-BOOT、不复位显卡**；开机任务日志里就是那句 `ACE-BOOT was never stopped`。
- 老版本（2026-10-12 之前）用过 `ThrottleStop.sys`，那一步确实要"杀托盘 → 停 ACE-BOOT"才能落地，**已退役**。
  包里还留着 `工具-测试与修复\ACE修复.cmd`，只给两种场合用：① 老机器自愈（把被改过的 ACE-BOOT 启动配置恢复回去）；
  ② ACE 自己被别的工具改坏时恢复 —— 新机器正常装机**用不到**。

> 上表右列只涵盖我们实际见过的几种方案，没有对市面上的包逐个核；归类依据是"解锁发生在哪一层"。
> 本包这一列的证据都在仓库 `docs/`、`evidence/` 与包内日志里，可以自己翻。
> **† 这三格是我们在见过的方案里的常见情况**，没有对市面上的包逐个核 —— 没核过的不写成「普遍如此」。

## 装之前：**进一次 BIOS，把这几项一次设完**（别等脚本报了再回去改）

**为什么现在设**：体检是在进 Windows 之后跑的；BIOS 里缺项的话，脚本会报"设置项未到位"，你还得再关机进一次 BIOS。
所以推荐**一次进 BIOS 全设好**，回来再跑脚本 —— 只进一次，后面就不会被体检打断。

**A. BIOS 里（一次改完，改完保存退出）**

| 项（各家叫法） | 设成 | 说明 |
|---|---|---|
| **Secure Boot**（安全启动） | **Disabled**（老华硕选 `Other OS`） | 硬门槛：解锁固件未签名，开着就不会被执行 |
| **CSM**（Launch CSM / CSM Support） | **Disabled** | 有这项就关；关着 CSM，above-4GB MMIO 才能被自动打开，也不容易把系统装成 Legacy |
| **Above 4G Decoding**（铭瑄板上叫 `Above 4GB MMIO BIOS assignment`） | **Enabled**（板子没这项就跳过） | 解锁固件要在 4 GB 以上放载荷；ReBAR 这条路径也要它 |
| **Fast Boot**（快速启动 / Ultra Fast） | **Disabled** | 开着可能跳过启动顺序直进 Windows，解锁固件那次开机就没跑到 |
| 该 x16 槽的 **PCIe 速率** | **Auto**（别锁 Gen1；Gen3/Gen4 也行） | 只影响 Gen2，锁死 Gen1 就永远上不了 Gen2 x16 |

位置（按关键词找）：华硕 `Advanced → System Agent (SA) Configuration`、技嘉 `Settings → IO Ports`、
微星 `Settings → Advanced → PCI Subsystem Settings`、华擎 `Advanced → Chipset Configuration`；CSM / Secure Boot / Fast Boot 都在 `Boot` / `Security` 页。

**B. Windows 里（顺手确认，不用重装）**

- **BitLocker**：关掉或**暂停**（否则改引导链会索要恢复密钥）；
- **系统盘 = UEFI + GPT**：MBR 盘先跑 `mbr2gpt`，否则装不进去；
- **杀软信任区**：火绒/360 把包目录 + `System32\drivers` 下那两个驱动加进信任区、关"启动项保护"。

> **不想动 BIOS 也行**：直接跑"三步装"第 2 步的**只读体检**（不碰硬件、不写任何东西），它会把缺的项逐条打出来并指路，
> 菜单 `x` = "我先去 BIOS 改这些，改完重跑"。但那样通常要多进一次 BIOS —— 所以我们推荐上面这条路线：一次设完。
> 主板 BIOS 里没有的项（常见于老平台/品牌机）直接跳过，体检也认得，不会因此判失败。

## 三步装（真的只有三步）

1. **把解压出来的文件夹整个拷到那台装 40HX 的电脑上**（U 盘 / 网络都行），放在哪都行（例如 `D:\40hx-oneclick`）。
2. **双击 `一键解锁40HX.bat`**（唯一入口）→ 它先跑一遍**只读体检**（约 10~15 秒，不碰硬件、不写任何东西），然后打印：
   - `★ 本机推荐：选项 X ——` 理由（按设备状态码 / 阻塞项 / Above 4G Decoding / ReBAR 现状判断，**不按 VBIOS 版本**）
   - `设置项体检`：哪些 BIOS 项没到位、**去哪儿开**（见下面「装之前确认」）
   → **直接回车 = 采纳推荐项**；也可以自己敲：`1` 算力+Gen2 ｜ `2` 再加 ReBAR 8 GiB ｜ `3` 只解 Gen2 ｜
     `f` 强行解锁 ｜ `r` 只体检 ｜ `u` 撤销 ReBAR ｜ `x` 我先去 BIOS 改设置项。首次约 1 分钟，它会自己弹管理员授权。
3. **完全关机再开机**（开始菜单 → 关机，**不是"重启"**，最好拔掉电源线等 10 秒）；开机时会先闪一段解锁固件跑码界面，
   进 Windows 后**双击 `状态自检.bat`** → 看到 `全绿 -- WDDM + PCIe Gen2 + 算力满血` = 成功。

> ⚠️ **为什么必须"关机"不能"重启"**：解锁由每次开机的固件写显卡寄存器实现，"重启"清不掉显卡残留状态；
> 残留状态不对就会表现成"开机黑屏一会儿 + 设备管理器里 40HX 提示**代码 43**"。

## 补充说明（清单里没写的几件事）

**装之前还差一件：显卡驱动装好、GSP 固件开着。** 没开时脚本会帮你写开关，但**必须完全关机**才生效（不是"重启"）；
`nvidia-smi` 里 GSP 显示 `N/A` 就是没开 —— 双击 `GSP体检.cmd` 会体检并按需自动修好（详见 `文档\使用说明-详细.md` 第 1.1 节）。

**装完之后再看一眼启动顺序**：BIOS 里 `40HX Unlock` 要排第一位，装完第一次开机**必须看到 40HX 跑码界面**。
NVRAM 里写对了 ≠ BIOS 真选了它（客户机实证）；没看到跑码界面 = 这次开机固件没被执行，回 BIOS 把它排第一。

**`Above 4G Decoding` / `CSM` 到底"必须"吗？**

- `Above 4G Decoding`：**不是绝对必须，但建议开**。我们核过的技嘉板该项默认是 `Disabled`（要手动开）；铭瑄平台上对应项的默认值
  我们的工具读不到（IFR 里没写）⇒ 现场进 BIOS 读实值。它管的是"设备能不能用 4 GB 以上地址"，而解锁固件正是在 4 GB 以上放载荷 —— 读不回来就卡在 `WPR2 NOT UP` /
  `IMEM[0]=0xffffffff`（固件层），下游表现就是每次开机代码 43。
- `CSM`：**建议关**，且与上一项**耦合**（不关 CSM，above-4GB MMIO 基本开不了）。
- 两项都设好还是解不开 → **下一步是升级主板 BIOS**：2026-10-15 实证，铭瑄 MS-TZZ H610ITX 2.5G 从 `E1.2G(2022-05)` 升到
  `E2.4G(2025-07)` 后，同一张卡 `WPR2 UP after 0ms → booter OK (attempt 1) → 解锁成功`（E1.2G 上同一处死活是 `WPR2 NOT up`）。
  ⚠ 这是**实测现象**、因果未定案；升级会重置 BIOS 设置，升完把上面那几项再核一遍。
- 可选实验项（**尚未定案**）：`Control Iommu Pre-boot Behavior` = `Disable IOMMU`。能解锁的技嘉板默认关、失败侧铭瑄板默认开，
  但客户那台铭瑄板在 E2.4G（仍默认开 IOMMU）下也解锁成功 ⇒ 这项解释不了全部现象，放在"还不行时再试"。

**体检与菜单（这些项不用自己记）**

- 想先只看不改：双击 `一键解锁40HX.bat` 选 `r`（只体检，什么都不改），或 `Install-40HXUnlock.ps1 -Mode Check`（0 项失败即环境 OK）。
- 体检会把没到位的项逐条打出来（含各家 BIOS 菜单路径与关键词），并给出口：菜单 `x` = "我先去 BIOS 改这些，改完重跑"，这一步什么都不改。
- **推荐项只是省事，不是限制**：菜单永远列全部选项，`f` 是给"还没找到解不开根因"留的强制通道（带 `-ForceLockedBatch`，锁死批次也照装）；
  但 Secure Boot / BitLocker / MBR 盘 / ESP 挂不上这四项**仍然会拦** —— 它们是"装了也不生效"，不是解锁能力问题。
- 逐条报错对照见 `排查指引.md` 第 3 节。

## 能解 / 不能解（2026-10-15 口径更新）

**一句话：不用再拿 VBIOS 版本号去猜了。** 2026-10-14 的交叉换机实证（案例库 C11）推翻了"版本号决定能不能解"这套口径：

同样两张 `90.06.67.00.06` 卡（VBIOS 内容几乎相同）：装在 **精粤 B660I** 上**两张都成功**（算力 + Gen2）；
换到 **铭瑄 H610ITX** 上**两张都失败**（固件起不来、PLM 关窗、每次开机代码 43）。
⇒ **同卡换板、结局翻转；换卡不换板、结局不变**：能不能解多半在**平台（主板 / BIOS 设置项 / BIOS 太老 / 64 位地址解码）**，
不在卡、也不在版本号。所以本包**不再按 VBIOS 版本给结论**，安装器只把版本号念一遍当记录。

那什么情况下真解不了？

| 情况 | 说明 | 怎么办 |
|---|---|---|
| **锁死批次**（POST 寄存器形态 `SS0=0x20000010`） | 算力 + Gen2 都解不了（写入回读硬锁，补写工具放行也写不进） | 安装前只读预检会认出来并问你要不要装；不装就退出（退出码 6，零改动） |
| **平台不配合**（解锁固件在开机阶段起不来） | 症状 = 每次开机代码 43；`40hx_log.txt` 里有 `PLM closed — no booter effect` / `abort:` | 见 `排查指引.md` §5.1c：先 `一键卸载.cmd` + **完全关机**清 43 → **按上面那张 BIOS 6 项表**把设置项设好 + **升级主板 BIOS** → 重装；**别急着判卡死刑**（同卡换板就成功过） |
| 其它没见过的形态 | 装完由那次开机自证 | 把 `一键诊断.cmd` 报告发回来攒样本 |

> **代码 43 ≠ 卡坏了**：解锁固件每次开机都会跑一遍，跑失败会留残留态，驱动就认不了卡。
> 自救两条：① 双击 `一键卸载.cmd` 还原；② 进 BIOS 把 Windows Boot Manager 调回第一启动项（40HX 项不跑就没有 43，Windows 侧 Gen2 工具照常工作）。

## 想连 ReBAR（8 GiB 大 BAR）一起开（选做）

ReBAR = 让显卡把整块显存一次映射出来（40HX 的 `BAR1` 从 **64 MiB** 变成 **8 GiB**）。跑 AI / 大显存负载更划算，纯玩游戏影响不大。

**只能在开机固件阶段开**（Windows 侧热改实测是死路），所以本包的做法是：把解锁固件换成**带 ReBAR 的版本**，并把它设为第一启动项。

| 步骤 | 怎么做 |
|---|---|
| ① 装 | 双击 **`一键解锁40HX.bat`** → 选 **2**（算力 + Gen2 + ReBAR）。体检会**先读"这块卡在 4G 以上有没有 MMIO 窗口"来判断 Above 4G 有没有开**并给出证据；选 2 时体检没过要输入 `FORCE` 再确认一次；装完驱动就位后还会自动跑一次**只读 BAR 探测**留证据 |
| ② 开机 | **完全关机再开机**。跑码界面里应出现 `[rebar] BAR1 8 GiB active` |
| ③ 复核 | 开机 1~2 分钟后双击 `状态自检.bat`：`[1/5]` 区块里的 `ReBAR` 行显示 **已启用（BAR1 = 8192 MiB）**；或 `nvidia-smi -q` 看 `BAR1 Memory Usage → Total = 8192 MiB` |
| ④ 不想留 | 双击 `一键解锁40HX.bat` 选 `u`（撤销：切回主线 EFI + 删 ReBAR 启动项与文件）；选 `1` 只切回主线 EFI（文件保留） |

**先试一次再决定（可选）**：双击 **`试跑REBAR.cmd`** —— 只对**下一次开机**生效一次（BootNext，不动启动顺序、不动 BIOS），
开机后约 2 分钟自动在本目录生成 `验证报告-latest.txt`（算力 / Gen2 / ReBAR / 代码43 全量核对）；不想留就 `试跑REBAR.cmd undo`。

**必须知道的三条**：

- 主板要 **Above 4G Decoding = Enabled**（这是 **ReBAR 这条路径**的前提；**纯算力解锁不要求**一定有这一项），并且有一块放得下 8 GiB 对齐空间的空闲 64 位 MMIO 窗口。**BIOS 里的 Re-Size Bar Support 开关在这条路径上不是必需的**。
- 不满足时 **EFI 会整体回滚**：系统照常启动，只是 ReBAR 没开（不会黑屏、不会进不去系统），EFI 日志里有原因。
- **大孔径平台（X99 / 双显卡，4 GB 以上的窗口被别的卡占着）**：固件会先按老办法找，找不到就把窗口放到「最低已用 4G+ 地址往下 4 GiB」再按 8 GiB 一块往下试；这条路复现了 X99 两台机器手工填进去的地址，一般不用你插手。实在不放心的可以在 `工具-测试与修复\` 里用 **`ReBAR-Window.cmd`** 手工指定窗口、**`ReBAR-Log.cmd`** 回读开机日志。
- 目前只在作者本机（B560M + 1 张 40HX + 驱动 616.92）实测过，其它主板/驱动/多卡未验证 —— 所以建议先 `试跑REBAR.cmd` 试一次，或直接走选项 2，随时能退。

## 正常现象（遇到别慌，不是坏了）

- 火绒/360 弹一次 `Exploit/Vulndriver.ad`：**预期**（这几个驱动都是内核级 BYOVD 工具），弹窗里选"信任"即可；被删了开机任务也会自动补回来（信任区怎么加见 `文档\使用说明-详细.md` 第 1.1 节）
- 安装时弹 UAC + 闪一个黑窗口：正常，装完按任意键关闭
- 装完第一次开机比平时慢几秒：先跑解锁固件、再回到 Windows，正常
- **开机后立刻双击 `状态自检.bat` 时 [5/5] 可能显示黄（未实测）**：开机自动重训那一轮要 1 到 3 分钟，脚本读日志时它还没跑完 ——
  等 2 到 3 分钟再跑一次就好。**跑一次「一键修复Gen2」就变绿、重启后又变黄，也是同一件事，不是解锁坏了**（2026-10-08 起脚本会把这种情况说成"未实测"而不是红）。
- **状态正常时不会再有"下一步-重启后看这里.txt"**（2026-10-02 起：只在"真有失败/还没验证过"时才生成，正常了自动清掉）
- **日志不会无限长大**：包内 `logs\` 只保留最近 10 份；机器上 `C:\ProgramData\CMP40HXGen2\windows\logs\postbind.log` 超过 64 KB 自动裁剪，`retrain-last.log` 每次开机覆盖；**只有失败那次**会另存到 `logs\failures\`（留证据用）
- **ACE 弹提示 / 游戏要"重启修复"**：本包不碰 ACE 的加载（不装 `ThrottleStop.sys`、不停 `ACE-BOOT`），正常装机不会出现；
  真遇到（多半是老版本残留）就用 `工具-测试与修复\ACE修复.cmd`，详见下一节与 `docs/06-ace-boot.md`

## 出问题怎么办（按现象找工具）

- **Gen2 到不了（一键修复Gen2 最后是 [!!]）**：先看它打印的"体检缺口"。缺口不为"无" = 解锁固件的 Gen2 预埋没写进去 →
  ① 重跑 `一键解锁40HX.bat`（选 `1`）→ **完全关机**再开机 → 再跑一次；② 还在 → 双击 `工具-测试与修复\补写Gen2预埋.cmd`（先试跑给你看，再补写，可回滚）。
  **2026-10-05 起**：对"解锁固件的基线门禁把这批卡拦掉了"的机器（ESP 日志里 `[efi-b] abort: baseline mismatch`），
  开机任务会**每次开机自动补写**（新路径带 `-AllowPrime`；实测 XVE_OVR 0→6 后 VSEC/LNKCAP/LNKCAP2/TLS 会自己到位，链路 Gen2 x16），
  寄存器易失所以必须每开机一次；健康机器上**补写分支**不写任何字节（重训本身仍会写根端口的 LNKCTL 目标速率位，这是本包原本就有的行为）。关掉它：**以管理员身份**创建空文件 `C:\ProgramData\CMP40HXGen2\NO_PRIME`（那个目录有 ACL 加固，普通另存会失败）；关掉后那一次开机只做普通重训、不补写预埋（2026-10-10 起已移除"停 ACE"的老路径，新路径失败只记日志）。注意：**完全关机不会持久关掉补写**——寄存器只是复位，若没有 NO_PRIME，下次开机又会补写。

## 解不开？（算力没解锁 / 每次开机代码 43）按这个顺序试 —— 别急着换硬件

**1. 先确认"跑没跑起来"**：装到位 + BIOS 里把 `40HX Unlock` 排到第一位 + **完全关机**（不是重启）再开机，开机时应该看到 40HX 跑码界面。没看到跑码 = 解锁固件没被执行，后面都不用谈。

**2. BIOS 三项，一次只改一项，改完完全关机冷启动再复测**：`Above 4G Decoding`（铭瑄板上叫 `Above 4GB MMIO BIOS assignment`）= **建议 Enabled**、`CSM` = **建议 Disabled**、`Fast Boot` = **建议 Disabled**。（还想再试一项可选：`Control Iommu Pre-boot Behavior` = `Disable IOMMU`。）

**3. 还不行**：扣电池 / 短接跳线**深度放电** + 载入 BIOS 默认设置，冷启动复测。（实测过：有客户就是靠这一步从"死活解不开"变成"解锁 + Gen2 + ReBAR 全部落地"。）

**4. 还不行**：**升级主板 BIOS**（尤其 2018–2022 年的版本）。升级会把 BIOS 设置复位 ⇒ **升完必须把第 2 步那几项重设一遍**再冷启动；能解开之后，再按"**负载下**复核链路"（Gen2 跑起来 ≠ 留得住：跑 20~30 分钟压力再看链路速率/温度）。

**5. 还是不行 → 先定"是板的问题还是卡的问题"**（只有一台电脑也能做，任选一条）：

- 找一块**已知能解的主板**（H610 / B660 这一级，二手也行）换上跑一次 —— **只换主板，别动 CPU / 内存 / 电源**；
- 或把这张卡拆下来，拿到 / 寄到一台**一定能解**的机器上跑一次；
- 或拿一张**已知能解的 40HX**，插到你这台机上跑一次。

　**能解 ⇒ 板 / 平台的问题；不能解 ⇒ 卡的问题**（这时候才谈换卡）。

> ⚠ 手上有第二张普通显卡（1060 之类）插**同一插槽**只能证明"插槽 / 供电没坏"，**不能**代替这一步。

**❌ 别做的四件事**：
① 降级 BIOS、来回刷；② 在同一块板上反复装 / 卸 / 刷 Gen2（症状会被搅乱，真实原因就看不出来了）；③ 一次改多项 BIOS 或同时换多个硬件（分不清是谁起的作用）；④ **没做第 5 步之前，别下"卡坏了"的结论** —— 我们实测过：同一套失败日志，换块板就解锁成功了。

**和显卡驱动 / Windows 版本有关吗？** 分工是这样：

| 环节 | 和显卡驱动 | 和 Windows 版本 |
|---|---|---|
| **算力解锁本身**（在进 Windows 之前就完成了） | **无关** | 无关（但 Secure Boot 开着会拦掉未签名固件 = 没跑） |
| 代码 **43** / 黑屏 | **强相关**：GSP 开关 `EnableGpuFirmware`（重装 / 升级驱动后会留在旧子键上失效）→ 跑 `GSP体检.cmd` 再**完全关机** | 间接：Windows"快速启动"开着时"关机"不是真冷启动，固件没重跑 |
| **Gen2** 落没落地 | **强相关**：重训由 Windows 侧发起，驱动没起来工具会 `exit 12` | 无直接关系 |
| 装不上 / BIOS 里看不到启动项 | 无关 | **相关**：分区表里没有 ESP、装机版把 Storage 模块精简导致误报 |
| 安装 / 工具跑不动（`exit 3` / `1450`） | —— | **相关**：内核隔离、"易受攻击驱动"列表、杀软会拦 `WinRing0` / `inpoutx64` |

我们已经跑通过的驱动不止一个版本（例如 `617.42`），**Win10 / Win11 上都有成功的机器**；关键是必须用**完整官方驱动包**（里面得有 `gsp_tu10x.bin`），`nvidia-smi` 里 GSP 显示 `N/A` 就是没开。
⇒ **"换个 Windows 版本试试"基本没用**；标准收尾是"重装驱动 → `GSP体检.cmd` → **完全关机**"。

## 原理（想搞明白再看）

- **算力**：ESP 上的解锁固件 `\EFI\40HX\40HXUNLK.EFI` 每次开机把 SS0/SS1 写回解锁值，并预埋 4 个 PCIe Gen2 策略寄存器 + 根端口 TLS。
  它来自 **OnlyEFI v0.1.1**（`BardKing-CN/CMP40HX-Unlock-OnlyEFI`，MIT），特点：EFI 阶段**故意不重训链路**，所以不会复位显卡 → 算力与 Gen2 可以并存。
  **正因为它在 UEFI 阶段完成，ACE 那一层根本参与不到** —— 这是本包"反作弊不用关"的机制来源（详见 `docs/06-ace-boot.md`）。
- **PCIe Gen2**：Windows 侧工具 `payload\windows\40hx-retrain-inpout.ps1` 用 `inpoutx64.sys` 直写 GPU BAR0（MMIO）+ `WinRing0x64.sys` 写 PCI 配置空间，只修两个被驱动改写的寄存器再重训根端口 → **全程不停腾讯 ACE-BOOT、不复位显卡**。
- **每次开机的自愈**：开机任务 `CMP40HX Gen2 PostBind`（SYSTEM）跑上面那套；成功率更高，驱动被杀软清了会自动从 ESP 兜底源补回；登录后 60 秒还有一次"补跑"。
- **ReBAR（选做那件）**：换用 `payload\EFI\40HXUNLK-REBAR.EFI` —— 同样是未签名的解锁固件，额外在 EFI 阶段配 XVE + 桥窗口，把 BAR1 放到 8 GiB；由本包自写的 `一键解锁40HX.ps1` 写进 ESP 并设为第一启动项。任一步失败就整体回滚，只在开机时生效。**Windows 侧改不了**（实测驱动会把 XVE 钳回 64 MiB）。

**出处与致谢**：本项目基于开源项目 **CMP40HX-Unlock（https://github.com/PZH1gdmu/CMP40HX-Unlock）** 改进。
上游提供了解锁原理、Gen2 研究结论与驱动思路（其 Windows 侧 helper 已全部被本包自写实现替代，包内无上游二进制）；本包把它做成"自含、可迁移、双击即装"的一键包，

ReBAR 版固件以 **Cyridd/cmpunlocker**（MIT，https://github.com/Cyridd/cmpunlocker）的 `unlock40x_v70.c` 为基线自行编译（在其基础上追加 Gen2 预埋与 ReBAR 配置）；Windows 侧另有 4 处做法借鉴该项目，逐项记在 `THIRD_PARTY.md`。
本包**不调用**上游安装器（它会覆盖 ESP 上的 OnlyEFI 固件 → Gen2 永远落不了地），固件/启动项/任务/驱动全部自己写。
