# 排查指引（装到别的电脑上报错时看这里）

> 适用：`Install-40HXUnlock.ps1` / `一键安装.cmd` 这套包。原则——**先取证，再动手**。
> 本文件按“报错关键字”组织，`Ctrl+F` 搜你日志里的原话即可跳转。

---

## 0. 30 秒流程

1. **看退出码**（本文件第 1 节有表）。脚本失败时会自己打印一个「出错怎么办」区块，里面已经把下面这几个路径写好了。
2. 完整日志在 `本包目录\logs\run-<日期>-<时间>-<模式>.log`（每次运行一个文件，失败就贴这个）。
3. 只体检、不改动：`powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Check`
4. 想退回去：`... -Mode Uninstall -Yes`（然后重启一次）

三条命令都能直接用：本包目录里 `Shift+右键 → 在此处打开 PowerShell 窗口`，或者用 `一键安装.cmd` 同款提权方式。

## 1. 退出码表

| 退出码 | 含义 | 先查 |
|---|---|---|
| 0 | 全部成功（可能有 `[提示]`，不影响功能） | —— |
| 1 | 有步骤失败 | 日志里的 `[失败]` 行 |
| 2 | 前提不满足 / 不是管理员 | 第 3 节、第 6 节 |
| 3 | 载荷缺失或被改动（sha256 对不上） | 第 2 节（杀软删过 / 没拷全） |
| 4 | 固件变量(NVRAM)读写失败 | 第 4 节 |
| 5 | 驱动或服务失败 | 第 5 节 |

`-Mode Check` 的退出码同样遵循这张表（Check 用 2 表示前提有问题，用 1 表示现状有失败项）。

## 2. 杀软（**最常见，先看这节**）

### 2.1 火绒弹「Exploit/Vulndriver.ad」——这是**预期**的

典型提示原文：

```
病毒名称：Exploit/Vulndriver.ad
病毒路径：C:\Windows\System32\drivers\ThrottleStop.sys      ← 或 %ProgramData%\...\ThrottleStop.sys
操作类型：修改
操作结果：已处理，删除文件
操作进程：C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
操作进程命令行：... -File ...\Install-40HXUnlock.ps1 -Mode Install
```

原因：`ThrottleStop.sys` 是 **BYOVD**（自带易受攻击驱动）类型的内核驱动，PCIe Gen2 那条路只能靠它，所有同类方案都会被报毒。不是包坏了、不是中毒。

**要做的事**：在火绒里把它放进信任区（**必须做，否则每次开机自愈会反复触发**）：

```
火绒安全 → 主界面右上「≡ / 安全设置」→「信任区」→ 添加：
  文件：C:\Windows\System32\drivers\ThrottleStop.sys
  文件：C:\Windows\System32\drivers\WinRing0x64.sys
  文件：C:\Windows\System32\drivers\inpoutx64.sys
  目录：C:\ProgramData\CMP40HXGen2
  目录：本包目录（例如 本仓库\40hx-oneclick）
```

如果安装时它已经删了文件：**不用重装**。脚本在开机任务里有 **多源自愈**（`C:\ProgramData\CMP40HXGen2\drivers`、`C:\ProgramData\40HXUnlock\drivers`，再加 ESP 分区 `\EFI\40HX\drv` 兜底——杀软不扫 EFI 分区）；首选路径要用的 `inpoutx64.sys/.dll` 由重训工具自己在每次开机时从上面那两个 `%ProgramData%` 目录补回。加完信任区后跑一次：

```
powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Repair
```

### 2.2 其它杀软

- **Windows Defender**：一般只隔离不解压出来的东西；若被拦，加排除项：`设置 → 病毒和威胁防护 → 排除项`，加 `C:\ProgramData\CMP40HXGen2` 与三个 `.sys`（ThrottleStop / WinRing0x64 / inpoutx64）全路径。
- **360 / 电脑管家**：除了文件信任，还要关掉它们的**「启动项保护 / UEFI 保护 / 引导区保护」**，否则第 4 节的固件变量写不进去（症状：退出码 4，`无法获得固件变量读写权限` 或 `写 Boot000x 失败`）。
- **联想/华硕自带的安全组件**（Lenovo Vantage、ASUS Armoury Crate 的启动项锁）同理。

### 2.3 腾讯 ACE-BOOT 拦驱动（游戏玩家机器常见）

**先说现在的默认行为（2026-09-29 起）**：开机任务首选 `40hx-retrain-inpout.ps1` —— 它用 `inpoutx64.sys` 直接 MMIO 写 GPU 寄存器，
**全程不停 ACE-BOOT**。所以正常机器上：

```
%ProgramData%\CMP40HXGen2\windows\logs\postbind.log  末尾应看到
  ---- NewPath start: ... -Apply ...
  ---- NewPath EXIT=0 ...
  PASS: Gen2 reached on the new path - ACE-BOOT was never stopped
```

这一段里**不该出现** `ACE-BOOT 已停止 / 已恢复运行` 这类行 —— 出现了说明走的是下面那条老路径。
逐条硬件读数在同目录 `retrain-last.log`（`pre:` / `writeOk=True readback=` / `GPU final: Gen2 x16 LNKSTA=0x1102` / `ROOT final: 0xF102`）。

只有新路径 **退出码非 0** 时才回落老路径（postbind.log 里会有 `NewPath did not PASS - exit=n - falling back to the legacy ACE path`），
那时才需要在运行的那十几秒里「停 ACE → 落地 Gen2 → 恢复 ACE」（必要时先结束托盘进程，因为托盘会把它卡在 STOP_PENDING）。**两种情况下都不需要手动禁用反作弊**。

新路径失败时按 `NewPath EXIT=n` 对号入座（工具自己的退出码，不是安装脚本的退出码）：

| n | 含义 | 先查 |
|---|---|---|
| 13 | `inpoutx64` 驱动没起来 | 多半是杀软隔离了 `inpoutx64.sys` → 加信任区 + `-Mode Repair`；或 `sc query inpoutx64T` 看服务状态 |
| 11 | 基线不认识 / 找不到 PCIe cap | 被别的工具改过寄存器或固件不是本方案写的（重跑一次 `Install` 写回 ESP 固件） |
| 12 | 120 秒内 GPU 没就绪 | 显卡驱动没起来 / 卡被复位过（Code 43）→ 冷启动 |
| 10 | 链路没到 Gen2 | 主板重训行为不同（少见）→ 仍走老路径，能落地就行 |
| 3 | `WinRing0` 不可用 | 服务/驱动缺失 → `-Mode Repair` |

老路径的症状（只在新路径失败时才需要看）：**算力是好的**（`40hx_log.txt` 有 `UNLOCKED`），但 `C:\ProgramData\CMP40HXGen2\windows\logs\last.log` 里是
`[SC] StartService 失败 31` / `FATAL: ThrottleStop service did not start`，开机任务 rc=30；同时开机弹「检测到与游戏可能存在兼容问题的软件程序加载: ...ThrottleStop.sys」。
这不是故障，老路径自己会处理：只要 `last.log` 里最终是 `PASS` + `EXIT=0` 就算成功。反过来，如果某次开机 ACE 恢复得比任务早，下一轮会重试，最多 3 轮。

**换安装目录 / 服务改名也照样处理**（这是有意的设计）：`ACE-Toggle.ps1` 不认死路径也不认死名字 ——
它找的是「正在运行 且 驱动 ImagePath 含 `AntiCheatExpert`」的驱动（没有才回退按名字 `ACE-BOOT` 找），托盘进程按可执行文件完整路径找（找不到才回退按映像名 `ACE-Tray.exe`）。
停止前会把**原始启动类型**记到 `logs\ace-state.json`，恢复时按记录还原，不会硬把启动类型改成 `system`。

怎么确认「就是 ACE 拦的」：
- `%ProgramData%\CMP40HXGen2\windows\logs\postbind.log` 里该次开机有 `StartService 失败 31` / `FAIL: post-bind step did not reach Gen2` / `EXIT=30`；
- 同时 `C:\Program Files\AntiCheatExpert\`（或你机器上的实际安装目录）里会多出一个 `ace-boot-<时间戳>.log`，时间戳就是那次拦截 —— 文件本身是加密/二进制的，看时间对不对得上即可，不用读内容；
- 算力不受影响：`40hx_log.txt` 该次开机仍有 `*** UNLOCKED ***`。

如果日志里出现 `ACE WARN: 检测到其它厂商反作弊正在运行…: vgk / EasyAntiCheat / BEDaisy …`，说明机器上还有**非腾讯**的反作弊在跑，
本脚本故意不碰它们。这种情况下若 Gen2 一直落地不了，只能人工确认放行 `ThrottleStop.sys`（或临时退出该反作弊）后再跑一次 `-Mode Repair` + 一次重启。
若日志出现 `ACE WARN: … 仍未停止 —— 本次重训很可能 EXIT=30`，说明该次没停成功（比如托盘是别的进程名、或被策略保护），下次开机会自动重试；
连续多次都这样，按上面 `-Mode Repair` 后手工确认一次。

## 3. 前提不满足（退出码 2）

| 日志原话 | 处理 |
|---|---|
| `固件不是 UEFI 模式` / `固件类型 : Bios —— 必须是 UEFI` | BIOS 里关 **CSM**、开 UEFI 引导；老盘是 MBR 还要 `mbr2gpt /convert /allowFullOS` |
| `系统盘不是 GPT` | 同上，MBR → GPT |
| `Secure Boot 开着` | BIOS → Security → Secure Boot → **Disabled**（本方案用的是未签名 EFI，必须关） |
| `BitLocker 开着（会索要恢复密钥）` | `manage-bde -status` → `manage-bde -protectors -disable C: -rebootcount 0`；或先在设置里暂停保护 |
| `没找到 CMP 40HX (DEV_1F0B)` | ①卡插紧、供电（6pin）到位；②装 NVIDIA 驱动；③有的机器要在 BIOS 里把 PCIe 槽设为 Gen1/自动并开 **Above 4G Decoding**；④设备管理器里看有没有带感叹号的未知设备 |
| `这个模式需要管理员权限` | 双击 `一键安装.cmd`（它自己弹 UAC）；**不要**直接右键 `.ps1` 运行（那样不提权） |

BIOS 里还建议（第 5 节“开机没解锁”也靠它）：

- **Above 4G Decoding = Enabled**（这是 40HX 类矿卡最常见的失败原因）
- **Fast Boot = Disabled**、**CSM = Disabled**
- PCIe 槽速度先设 `Auto`（解锁后才谈 Gen2）

## 4. ESP 与固件启动项（退出码 4 / 3）

| 日志原话 | 原因与处理 |
|---|---|
| `ESP 挂载失败（需要管理员；或 ESP 被 BitLocker/其他工具占用） ; mountvol 报: ...` | ①确认是管理员窗口；②手动 `mountvol` 看盘符占用（本脚本会先找已经挂载出来的 ESP，再找空盘符挂）；③BitLocker 开着挂不上；④**虚拟机/WSL 里跑不了**，要在真机跑；⑤第三方的分区工具占着 ESP，关掉再试 |
| `无法获得固件变量读写权限` / `写 Boot000x 失败` | ①管理员；②关掉安全软件的「启动项/UEFI 保护」（见 2.2）；③极少数老主板不支持写固件变量 → 走 BIOS 手设（见下） |
| `回读 Boot000x 失败` / `回读内容与写入不一致` | 个别主板对某些 `Boot####` 槽位处理异常。重跑一次；还不行就**进 BIOS 手动选启动项**（也可以加 `-WriteBootx64` 让解锁固件顺带写到 `\EFI\Boot\bootx64.efi` 做兜底——默认不写它，避免动 Windows 自己的引导文件）。备份的原始字节在同一次运行的 `backup\<时间戳>\` 下 |
| `没有空闲 Boot#### 槽位` | NVRAM 满（少见）：进 BIOS 启动项里删几个没用的 |
| `BootOrder 写入失败` | 同上；或直接进 BIOS 把「40HX Unlock」排到第一位（启动项已经建好了，只差排序） |
| 装完**开机不进** `40HX Unlock`，但 Windows 能正常进 | 这是主板的固件启动项排序被别的系统改写（Windows 更新、双系统、PE 工具都会干这事）。三种办法：①重跑 `-Mode MakeDefault`；②进 BIOS 启动项手动选一次；③加 `-WriteBootx64` 重装一次，用 `\EFI\Boot\bootx64.efi` 兜底（默认没写它；BBS 里把硬盘设为第一启动项即可） |
| 想临时试一次、不落盘 | 加 `-BootMode next`，只设 `BootNext`（跑一次自动恢复，最安全） |

**验证启动项是否真的写进去了**（不重启也能看）：

```
bcdedit /enum firmware          :: 应能看到 description 带 40HX Unlock 的条目
powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Check
```

`-Mode SelfTest` 会做无损自检：ESP 读写往返、NVRAM 写入→逐字节回读→删除、BootOrder 原样写回，用临时槽位，不碰你正在用的项。

## 5. 装完完全关机再开机后“没效果”（退出码 0 但结果不对）

先分清是**算力**没解锁还是 **Gen2** 没落地，判据完全不同：

| 现象 | 判据在哪 | 说明 |
|---|---|---|
| 算力没解锁 | ESP 根目录 `40hx_log.txt` 有没有 `*** UNLOCKED (SS0=0x88888888 SS1=0x8) ***`，看它的时间戳是不是**本次开机** | 没有这一行 / 时间是上次开机的 → **EFI 没被执行**（去第 4 节“开机不进 40HX Unlock”） |
| Gen2 没落地 | 先看 `%ProgramData%\CMP40HXGen2\windows\logs\postbind.log` 末尾：`PASS: Gen2 reached on the new path` = 新路径成功（ACE-BOOT 没被停）；若出现 `falling back to the legacy ACE path`，同段的 `NewPath EXIT=n` 就是新路径失败的原因（见 2.3 的表），再看老路径 `logs\last.log` 末尾要有 `PASS:` 与 `EXIT=0`；有 `GUARD=PASS SS0=0x88888888` 说明守卫通过 | 老路径 `EXIT=0` 但 `already physical Gen2 x16` 也算成功（已经是 Gen2，无需再写） |
| 两个都看着像坏的 | `-Mode Verify` 一次看结论 | 结论行会写「算力解锁 PASS/FAIL + PCIe Gen2 PASS/FAIL」 |

### 5.1 GSP 没开 → 代码 43 / 黑屏（2026-09-30 新增，客户机高发）

**症状**：装完提示全部成功 → 重启/开机后**黑屏 1~2 分钟**才进系统 → 设备管理器里 `CMP 40HX` 是**黄色感叹号（代码 43）**。

**判据（一条就够）**：看 `nvidia-smi -q` 里的 GSP 行

- 显示**版本号**（如 `615.71.08`）＝ GSP 已启用（正常）
- 显示 `N/A` ＝ **GSP 没开** ← 就是它。解锁固件把算力解开后，没有 GSP 的 `nvlddmkm` 认不了这张卡 → 黑屏一段时间 + 代码 43
- 没有这一行 / 找不到 `nvidia-smi.exe` ＝ 驱动没装好，先装驱动再谈解锁

**修（两条一起做）**：

1. 确认开关在**正确位置**（Windows 上写这里才生效；实测 `Services\nvlddmkm\Parameters` 里 0 匹配）：
   `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}\<000X>` 的
   `EnableGpuFirmware = 1`（DWORD）—— 取 `MatchingDeviceId` 含 `ven_10de&dev_1f0b` 的那个子键。
   2026-09-30 起的 `-Mode Repair` 会自动写对位置（日志出现 `GSP 开关已写: 显示类子键 0001 ... <无> -> 1`）。
2. **完全关机**（开始菜单 → 关机，最好拔电 10 秒）再开机，然后 `-Mode Verify` 复核：
   结论必须是 `GSP 固件 : PASS (版本号)` + `40HX 设备 : OK（没有代码 43）`。

> 旧包（2026-09-29 及以前）有两个坑会让 GSP 永远开不起来，别再用旧包：
> ① 把 `nvidia-smi` 里的 `N/A` 当成“已开启”；② 把开关写在 `Services\nvlddmkm\Parameters`（驱动不读那里）。
> 只读取证 + 一键修复见 `工具-测试与修复/诊断包-20260930/`（`一键诊断.cmd` / `修复-GSP.cmd`）。

**情况 B：开关本来就是 1，但 GSP 还是 `N/A`（2026-09-30 客户机实遇）**

日志会写：`GSP 开关已写: 显示类子键 0002 [...] EnableGpuFirmware 1 -> 1`（写之前就已经是 1）。这说明**不是开关的问题，是驱动从来没在开机时重新初始化过**：

| 原因（按概率） | 判据 | 处理 |
|---|---|---|
| **快速启动开着**（"关机"=混合关机，内核/nvlddmkm 从 hiberfile 恢复） | `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power` 的 `HiberbootEnabled = 1`（诊断报告第 1 节也会打） | `-Mode Repair`（会自动写 0），或 控制面板→电源选项→选择电源按钮的功能→更改当前不可用的设置→取消"启用快速启动"；然后**完全关机**再开机 |
| 装完驱动后一直没真正冷启动过 | 上次开机时间早于驱动安装时间 | 完全关机（不是重启）再开机 |
| 驱动包被裁剪，缺 GSP 固件 | 诊断报告第 4 节"驱动库里的 GSP 固件文件"里没有 `gsp_tu10x.bin` | 换官方完整驱动包重装，再冷启动 |
| 开关写在了非权威子键 | 诊断报告第 0 节"权威显示类子键"（`Enum\<实例>\Driver`）与写入的子键号不一致 | 2026-09-30 起 `-Mode Repair` 会按权威子键写；把报告发回来核对 |

处理完仍 `N/A`：跑 `工具-测试与修复\诊断包-20260930\一键诊断.cmd`，把报告发回来（报告里 GSP 行、权威子键、快速启动、GSP 固件文件都在第 0/1/4 节）。

### 5.2 Gen2 没落地 —— 按这个顺序看（2026-09-30 客户机 VBIOS .06 实遇）

算力 OK、设备管理器也没有 43，只是 `postbind.log` 写 `falling back to the legacy ACE path` / 任务 rc=0x1F(31)：
先打开 `%ProgramData%\CMP40HXGen2\windows\logs\retrain-last.log`，从上往下看这几行：

| 日志行 | 含义 / 处理 |
|---|---|
| `vbios/driver: 90.06.67.00.06, ...` | 显卡 VBIOS 批次。**批次不同 → Gen2 基线不同**（2026-09-30 起工具按“位”判定，不再写死常量：`LINK_CONFIG_0` 的 Gen2 位 = bit18 清 0；`PRIV_MISC_1` 的 Gen2 位 = bit13 置 1；bit11 是批次跳线位，原样保留） |
| `GUARD = FAIL ... baseline not in known family` | 基线仍不在已知族内 → 工具**拒写**（这是保护）。把这条日志发回来，补进族里再发新包 |
| `plan  : LINK_CONFIG_0 0x… -> 0x80085800 (Gen2 bit18=0)   PRIV_MISC_1 0x… -> 0xE0B42D00/0xE0B42500 (Gen2 bit13=1)` | 工具将要写入的目标值。`.04` 卡目标是 `0xE0B42D00`，`.06` 卡是 `0xE0B42500`（其余不动） |
| `LINK_CONFIG_0 already at target` / `PRIV_MISC_1 already at target` | 已经是 Gen2 态 → 幂等、不写（正常） |
| `GPU1/GPU2 SET_ONLY ...` | 只重训根端口没到时，2026-09-30 起会再对 **GPU 自己那条链路**做 SET_ONLY（厂商 helper 也是 root/GPU 交替重训），仍不写策略寄存器、不复位设备 |
| `WinRing0 start type=DISABLED -> fixing to demand` | 服务启动类型被 360/ACE/易受攻击驱动列表改成“禁用”了（老路径表现为 `sc start 失败 1058`）。2026-09-30 起每次开机自动纠正回 demand |
| `cleanup: WinRing0=STOP_PENDING` | 以前会一直停不干净（工具自己的句柄没关）；2026-09-30 起收尾先 `CloseHandle` 再 stop → `STOPPED` |
| `after cleanup: … STATE : 3 STOP_PENDING`（inpoutx64T） | `inpoutx64T` 是临时服务，stop 后 SCM 显示 STOP_PENDING 属正常，工具随后 `sc delete` 删掉服务；下一次看是 `1060`（不存在） |

### 5.3 安装/修复**中途异常退出**，报“文件正由另一进程使用 / 访问被拒绝”

原话长这样（客户机 2026-09-30 21:48 实测）：

```
使用“2”个参数调用“WriteAllBytes”时发生异常:“文件“C:\Windows\System32\drivers\WinRing0x64.sys”正由另一进程使用，因此该进程无法访问此文件。”
```

**原因**：`WinRing0_1_2_0` 停在 `STOP_PENDING`（驱动镜像还挂在内核里，有进程占着句柄）→ .sys 被锁 → 老版本安装器**没兜住这个异常**，
加上脚本里 `$ErrorActionPreference='Stop'`，整个 Repair 就地中断（后面的 helper 拷贝、任务注册、`-RunNow` 全没执行）。

**2026-09-30 起的行为**（`Save-PayloadFile`）：
1. 目标文件哈希**已经一样** → 直接 `已是同一份，跳过写入`（客户机就是这种情况，压根不碰锁，天然不报错）；
2. 不一样 → 写失败时**先 `sc stop <服务>` 再重试一次**（实测能自愈：日志会写 `重试后写入成功`）；
3. 仍失败 → 记一条 `[提示] … 写不进去` + 结尾待办，**不再中断**；完全关机再开机后开机任务会从 ESP 兜底源自动补齐。

**手工救急**（不等新包也想立刻推进）：
```cmd
sc stop WinRing0_1_2_0
sc stop ThrottleStop
:: 然后重跑一次 Repair 即可；要是 sc stop 也停不掉（一直 STOP_PENDING），先完全关机再开机再跑
```

**注意**：EFI 侧也有同一道基线检查。`ESP 的 40hx_log.txt` 里若出现
`[efi-b] abort: baseline mismatch; zero Gen2 research writes`，说明解锁固件也认为这张卡的 Gen2 基线不认识、主动放弃了 EFI 侧写入
（`工具-测试与修复\诊断包-20260930\一键诊断.cmd` 会在第 7 节直接标出来）。这种情况下靠 Windows 侧工具补写；两边都不认就把两份日志发回来。

注意两个**假警报**：

- `nvidia-smi` 的 `pcie.link.gen.current` **不可信**：空闲省电或纯计算负载时可能一直显示 1，即使实际已经是 Gen2。看 Gen2 用新路径的 `retrain-last.log`（`GPU final: Gen2 x16 LNKSTA=0x1102` / `ROOT final: Gen2 x16 LNKSTA=0xF102`）、老路径的 `last.log` 的 `GPU final: Gen2 x16`，或 `状态自检.bat` 的实测带宽（Gen2 约 5.7~6.2 GB/s，Gen1 只有 3.2~4）。
- 关机前读出来的 `SS0=0` / `0xFFFFFFFF` 是假读数（驱动用完即卸，本来就读不到）。以开机的 `40hx_log.txt` 为准。

若某次开机 Gen2 没落地：等 1~2 分钟看任务重试的结果，或手动跑
`schtasks /run /tn "CMP40HXGen2 PostBind"` → 再看 `postbind.log` 末尾（新路径的 `PASS` 行或 `NewPath EXIT=n`）和老路径的 `last.log`。
仍失败就 `-Mode Repair` 补齐驱动/服务（驱动的缺失 90% 是杀软干的，见第 2 节）。

### 5.4 【安全红线】绝不允许盲扫物理地址 —— 以及万一触发了怎么恢复

**红线**：任何写进工具的代码，**不得对未由操作系统声明的物理地址做读写**（"盲扫"）。只允许访问两类窗口：
① 系统已分配的资源（`Win32_PnPAllocatedResource` 里该设备名下的 BAR）；② 经验证属于该设备的窗口（如 ECAM 校验通过后）。
本工具已在 `MmioRead/MmioWrite/MmioReadN/MmioWriteN` 里加了**硬护栏**：窗口外一律拒绝并记
`[安全护栏] 拒绝访问未登记物理地址 …`。

**2026-09-30 真实事故**：为了在 WinRing0 被策略封杀的客户机上找 ECAM 基址，代码去盲读
`0x80000000/0x90000000/…/0xF8000000` 一串地址 —— 客户机主板把那片区域里的一个地址解成了平台空洞，
**读一下就触发平台致命错误，当场蓝屏；由于错误被锁存在 PCIe 根复合体里，之后每次重启都
`WHEA_UNCORRECTABLE_ERROR`**。

**现场恢复步骤（按顺序，第 1 步通常就好）**：
1. **完全断电冷启动**（不是重启！）：长按电源键 5~10 秒关机 → **拔电源线**（有电池也断开）→ 等 30~60 秒 → 开机。
   锁存的 WHEA 错误只有彻底断电才清得掉；普通重启芯片组状态不重置，所以会一直蓝屏。
2. 仍蓝屏 → 进 BIOS **载入默认设置**（F9→保存退出）；能选的话把该 x16 插槽临时设为 **Gen1**、并关掉 **PCIe AER**。
3. 仍蓝屏 → 断电、**拔出显卡**（显示器接核显可正常进系统）→ 开机进系统一次 → 关机断电 → 插回卡 → 开机。
4. 仍蓝屏 → 清 CMOS（跳线/电池放电）。

**说明**：这类错误**不损坏硬件、不丢数据**，只是错误锁存导致每次开机都被判定为致命。恢复后算力解锁、驱动、系统都不受影响。

## 8. Gen2 写不进去：`WinRing0_1_2_0` 服务名被别的软件占用（2026-10-01 客户现场实录）

**症状**（三种同时出现基本就能定性）：
- `sc config WinRing0_1_2_0 start= demand` 改完**立刻又变回 `DISABLED`**
- `sc start WinRing0_1_2_0` → **1058**（已被禁用）；换备用名 → **失败 2：系统找不到指定的文件**（那个文件其实存在）
- `sc qc WinRing0_1_2_0` 的 `BINARY_PATH_NAME` **不是**我们放的驱动，例如
  `\??\C:\Program Files\iGameCenter\WinRing0x64.sys`（七彩虹 iGame Center 自带的那份）
- `STATE : 3  STOP_PENDING`（它那份驱动还挂在内核里，卸不干净）

**根因**：WinRing0 的服务名是**公用资源**。七彩虹 iGame Center 以及部分显卡/主板工具都自带一份 WinRing0，
占着 `WinRing0_1_2_0` 这个名字。我们的旧工具也用这个名字 → 建不了、起不来、设备也开不了 →
**Gen2 策略寄存器（LINK_CONFIG_0 / PRIV_MISC_1）写不进去**，链路就只能停在 Gen1
（EFI 侧还有一道"卡批次/基线"的关，两道同时堵就必然 Gen1）。

**修复（2026-10-01 起的工具已内置）**：
1. 检测到该名字被别的软件占用时，**绝不改动别人软件的配置**，改用独立服务名 **`WinRing0_40HX`**
   （指向我们校验过的 `WinRing0x64.sys`）。WinRing0 的设备名是驱动内部固定的 `\\.\WinRing0_1_2_0`，
   所以换服务名不影响工具打开设备。
2. 若占用者那份**正在运行**（`RUNNING`）→ 工具**直接复用它创建的设备**，不再自己加载。
3. 若占用者那份卡在 `STOP_PENDING`（设备名被占着，谁也加载不了）→ 日志会明确提示：
   **先退出 iGame Center（托盘右键退出），或重启后先别启动它，再跑工具**。

**客户侧操作**：跑之前退出 iGame Center；保险做法是任务管理器 → 启动项里禁掉它自启，然后重启。跑完按需开回来。

## 9. 解锁成功后「ACE 过不了」——开机任务旧逻辑 BUG + ACE 优先模式（2026-10-01）

**症状**：Gen2 解锁成功，但进游戏时 ACE（腾讯反作弊）起不来 / 报初始化失败。

**根因（代码级，已修）**：`RunPostBind.cmd` 旧版把 ACE 的恢复写成
```bat
if "!RC!"=="0" if "!ACE_STOPPED!"=="1" call :ace_toggle on
```
即**只有 Gen2 成功时才恢复 ACE-BOOT**。于是出现这条链：
1. 某一轮开机：新路径没通过 → 回落旧路径 → 旧路径**临时停掉 ACE-BOOT** → 这一轮重训又失败（RC≠0）
2. → **ACE-BOOT 永远停在 STOPPED**（没人去恢复它）
3. 此后每一轮开机若新路径直接成功，第 17 行就 `exit /b 0` 返回了，**更不会**去恢复它 → 游戏里 ACE 一直起不来

**处理步骤（客户侧）**
1. 双击 **`工具-测试与修复\ACE修复.cmd`** → 看只读体检报告（桌面 `40HX-ACE体检-*.txt`）；报告会直接指出"ACE 引导驱动没在跑"
2. 双击 **`工具-测试与修复\ACE修复.cmd /fix`**（会弹 UAC）→ 它会：
   - 先把**开机任务脚本就地打补丁**（修掉上面的 BUG，自动备份 `RunPostBind.cmd.bak-<时间>`）
   - 调 ACE-Toggle 恢复 ACE-BOOT（按记录恢复原始启动类型并启动）+ 拉起 ACE 托盘
   - 仍不行则硬兜底：直接恢复启动类型并 `sc start`
3. **重启一次**（让预启动反作弊与游戏重新握手；ACE-BOOT 的启动类型没被改过，重启本身通常就能恢复）

**ACE 优先模式**（给"必须能玩腾讯游戏"的机器）：
```
工具-测试与修复\ACE修复.cmd /acefirst on     ← 开机任务永不停止 ACE-BOOT（代价：新路径不通时本轮不落地 Gen2）
工具-测试与修复\ACE修复.cmd /acefirst off    ← 恢复默认
```
实现：`C:\ProgramData\CMP40HXGen2\NO_ACE_TOGGLE` 标记文件；`RunPostBind.cmd` 读到它就跳过旧路径与 ACE 停止。
**注意**：该模式由新版 `RunPostBind.cmd` 读取 → 先跑一次 `工具-测试与修复\ACE修复.cmd /fix`（会打补丁）或安装器 Repair 部署新版。

**如果 ACE 报的是「环境异常 / 检测到第三方程序」**：那不是组件坏了，而是判定环境被改造 —— 本包不做任何
"破解反作弊"的事（封号风险）。可选：① 开 ACE 优先模式；② 让工具驱动只在开机十几秒内驻留（跑完即清理，日志有 `drivers cleaned`）；
③ 二选一：这台机器上"玩该腾讯游戏"或"用 Gen2 解锁"。

**对照证据（本机）**：`ACE-BOOT=RUNNING` + `ACE-Tray` 在跑 + Gen2 x16 正常 → **共存是可行的**；
本机 `ace-state.json` 显示 2026-09-29 那次停机 `Resumed=true`（那一轮 RC=0 所以恢复了）→ 说明恢复逻辑本身有效，只是漏了 RC≠0 的路径。

## 10. 游戏报「检测到与游戏可能存在兼容问题的软件程序加载: ThrottleStop.sys」（2026-10-01 客户实录）

ACE 弹窗原文：
```
腾讯游戏反作弊预启动模式
检测到与游戏可能存在兼容问题的软件程序加载:
C:\Windows\System32\drivers\ThrottleStop.sys
您可以右键退出或卸载腾讯游戏反作弊预启动模式"以加载该程序，但游戏启动时会要求重新启动电脑。
```
**这说明 ACE 完全正常**，它在按设计工作：ACE-BOOT 会在**映像加载阶段**拦截 ThrottleStop.sys。
我们包里那个老驱动 `ThrottleStop.sys` 一旦被加载进内核，游戏就进不去。

**关键认知**：新路径（inpoutx64 + WinRing0）**不需要 ThrottleStop**。本机对照：`ThrottleStop = STOPPED`（映像没加载）
而 Gen2 正常 x16、ACE-BOOT 与 ACE-Tray 都在跑 → **去掉 ThrottleStop 就等于解决**。

**新策略（2026-10-01 起）**
- 开机任务每轮先做「ThrottleStop 退场」：正在跑就 `sc stop`，启动类型设 `start= disabled`
- `heal` 段**不再自愈/创建** ThrottleStop（只保留 WinRing0 的自愈），也不再从 ESP 恢复 ThrottleStop.sys
- 旧路径 fallback 例外：它会临时 `start= demand` + `sc start`（在 ACE 已被它停掉的窗口内），跑完立刻 `sc stop` + 禁用
- `工具-测试与修复\ACE修复.cmd /fix` 会：① 把开机任务脚本升级为包内新版（本机被改写过的那行会回填，自动备份）
  ② ThrottleStop 退场 ③ 恢复 ACE-BOOT 与 ACE 托盘 ④ 输出报告

**客户操作**：`工具-测试与修复\ACE修复.cmd /fix` → **重启一次**（保证内核映像彻底卸载，ACE 自己也这么要求）→ 进游戏。

**注意**：不要用「退出/卸载腾讯反作弊预启动模式」那条路（那是 ACE 给的反向放行，会让游戏要求重启且降低反作弊保护）。
正确做法是让我们的驱动退场，反作弊保持原样。

## 11. 厂商遗留 / 七彩虹驱动 / 系统级改动的安全策略（2026-10-01）

### 11.1 厂商 v3.x 遗留启动项导致 ACE 报错 —— 新包会自己接管
**厂商 v3.x（含 v3.2）会留下三类东西**：计划任务（`40HX PCIe Gen2 Bring-up`、`40HX-Gen2-Retrain`）、
HKCU/HKLM `Run` 值（如 `40HXGen2` / `40HXGen2_parked`）、以及指向 `ThrottleStop.sys` 的服务。
它们会在**每次登录/每次开机**重新部署或加载 ThrottleStop → 腾讯 ACE-BOOT 拦下并弹「检测到与游戏可能存在兼容问题的软件程序加载」。

**新包的处置（默认只"停 + 置 disabled"，不动文件；只有显式 `/fix -retirefile` 才删服务、挪文件）**
1. **开机任务每轮复查**（`RunPostBind.cmd` 的 `TAKEOVER OF VENDOR LEFTOVERS` 段）：
   扫任务名/动作含 `40HX|Gen2|ThrottleStop|40HXUnlock` 的任务（**排除我们自己的** `CMP40HX Gen2 PostBind`）→ `schtasks /change /disable`；
   扫指向 `ThrottleStop/40HXUnlock` 的驱动服务 → 停 + `start= disabled`；每步写 `postbind.log`（`vendor: disable task …`）。
2. **ACE修复.cmd**：体检第 **6c** 节列出所有厂商遗留项；`/fix` 的 **[0b]** 步禁用它们并把原始状态留档
   （`%ProgramData%\CMP40HXGen2\windows\logs\vendor-disabled-*.txt`）。
3. **ThrottleStop 退场（默认：只停 + 置 disabled，不动文件）** —— 2026-10-04 起改为默认不挪文件，理由是：
   ACE-BOOT 拦的是**驱动映像加载**，不加载就够（本机实测：`.sys` 在盘上、服务从未加载，近 30 天 0 条弹窗事件）；
   而文件留着才能保住厂商 **legacy Gen2 回退**（AutoRetrain 需要 ThrottleStop）—— 新路径还不通的机器靠它兜底；
   服务键也保留 → 要用回 legacy 只要 `sc config <服务名> start= demand` 再 `sc start`。
   **彻底退役**（删掉指向它的服务 + 把 `ThrottleStop.sys` 从 System32 与各 heal 源目录挪到 `drivers-disabled\<来源>\`）
   才用 `ACE修复.cmd /fix -retirefile`；此后厂商 legacy 回退不可用（还原 = 把备份文件移回原处）。
4. HKCU 的 `Run` 值 SYSTEM 任务改不了 → 由 `ACE修复.cmd /fix` 处理（移除 + 留档，`/restoreautorun` 可还原）。

> 实测（本机，2026-10-01 16:59）：跑一遍新版 `RunPostBind.cmd` 的输出——
> `vendor: disable task "\40HX PCIe Gen2 Bring-up"` / `vendor: disable task "\40HX-Gen2-Retrain"` /
> `throttle: set ThrottleStop start= disabled` → 随后 `PASS: physical Gen2 x16 reached, the anti-cheat was never stopped`，
> 退出码 0，`ThrottleStop = DISABLED`、`ACE-BOOT = RUNNING`。

### 11.2 七彩虹 iGame Center 占用 WinRing0 —— 新包自动避让
现象：`sc qc WinRing0_1_2_0` 的路径是 `C:\Program Files\iGameCenter\WinRing0x64.sys`，
启动类型被改成 `DISABLED`、状态 `STOP_PENDING` → 老工具「建不了/起不来/设备开不了」→ Gen2 写不进去。

处置（已内置）：
- 工具**默认优先用 ECAM**（`inpoutx64` 直读 PCI 配置空间，**完全不依赖 WinRing0**）→ 客户机就是这么解锁成功的；
- 需要 WinRing0 的路径上，检测到公用名被占用就**不改动别人的配置**，改用独立服务名 `WinRing0_40HX`；
- 占用者那份**正在运行**时直接复用它创建的设备；
- 安装器体检会打印一行提示（检测到 iGame Center → 已自动避让），并附"如仍写不进去：先退出 iGame Center"。

### 11.3 「删掉启动项导致系统起不来」——更好的做法
**机制上**：`Run` 项在**登录阶段**才执行，删掉它不会让人进不了系统（最多某个程序不启动）。
客户机那次"卡转圈/登录后黑屏只剩鼠标"，更可能是**我们把 ACE-BOOT 从停用状态强行恢复成启用**造成的
（客户此前点过 ACE 弹窗里的"退出/卸载预启动模式"，两边状态不一致）。

**因此定下的规矩（已实装）**
1. **分级处置**：只读探测 → **禁用**（可一键还原）→ 最后才删；删除前必须记录原始配置 + 提供还原入口。
2. **动 ACE-BOOT 前先判一致性**：`ACE-Toggle -Action On` 只在「服务仍存在」且「当前启动类型不是 `DISABLED`」时才恢复；
   服务不存在（ACE 卸载过）或已被 ACE 禁用 → **一律不动，只记日志**。
3. **一切改动可回滚**：留档目录统一在 `%ProgramData%\CMP40HXGen2\windows\logs\`（`autostart-removed-*.txt`、`vendor-disabled-*.txt`、`ace-state.json`）
   + `RunPostBind.cmd.bak-*` + `drivers-disabled\`；一键还原 `ACE修复.cmd /restoreautorun`（桌面恢复包内同名开关）。
4. **救援顺序（写进客户指引）**：① 彻底断电冷启动 ② 启动菜单选 `Windows Boot Manager` 绕过解锁项
   ③ 安全模式里 `sc config ACE-BOOT start= disabled` + `sc stop ACE-BOOT` ④ 游戏客户端里"修复/重装 ACE"。

## 12. 每次开机都要手动跑一次「一键修复Gen2」才生效（2026-10-01 起的版本已修）

**先确认版本**：`payload\windows\40hx-retrain-inpout.ps1` 里应有 `TOOL_VER = '20261002-quiet'`
（版本号随每次出包更新，以文件里的实际值为准；对不上说明包和工具不是同一批）。
旧包请用新版，然后跑一次 `-Mode Repair`（或双击 `一键安装.cmd` → 修复）。

这一版修掉了三件事（详见 `文档/验证记录.md` 第 10 轮）：WinRing0 不可用时**自动回落 ECAM**；
ACPI `MCFG` 表 ID 打包错误导致 ECAM 一直拿不到基址；开机路径跑新工具之前**不做驱动自愈**。
并新增 `CMP40HX Gen2 PostBind Logon`（登录后 60 秒自动补跑一次）——开机那轮失败时不再需要你手动点。

**还想自查的话**，看这两个日志（都是 UTF-8，记事本/微信都好读）：

1. `C:\ProgramData\CMP40HXGen2\windows\logs\postbind.log`（每次开机的总账）
   搜 `---- NewPath EXIT=` 后面那个数字：
   - `0` 成功（同一行附近还会有 `PASS: Gen2 reached on the new path`）
   - `3` WinRing0 与 ECAM 都不可用 —— 看 `retrain-last.log` 里 `MCFG:` / `ECAM:` 两行；
     若 `ECAM 没有拿到任何系统声明过的配置空间基址` 说明是新版之外的老包
   - `13` `inpoutx64T did not reach RUNNING` —— 杀软/ACE 拦了 inpoutx64 的加载（把
     `C:\Windows\System32\drivers\inpoutx64.sys`、`C:\ProgramData\CMP40HXGen2` 加进信任区）
   - `12` 120 秒内 GPU 未就绪 —— 开机太早，登录后补跑任务会兜住
   - `11` 基线不认识 —— 把这块卡的 VBIOS 版本发回来（`nvidia-smi --query-gpu=vbios_version --format=csv`）
2. `C:\ProgramData\CMP40HXGen2\windows\logs\retrain-last.log`（工具逐条读数）
   重点看 `backend`（`WinRing0` 还是 `ECAM`）、`MCFG:`、`GUARD =`、`GPU final:`、`ROOT final:`。

**若日志里一个 `Add-Content` 报错都没有、`NewPath EXIT=0` 也出现，但开机后链路还是 Gen1**：
把这台机器的 `postbind.log` + `retrain-last.log` 发回来，同时跑 `状态自检.bat` 留一份结论。
## 13. 高风险动作速查（2026-10-01b）

完整版在包内 `文档/风险与恢复.md`。这里只放"最容易把客户机器搞坏的三件事 + 兜底"：

| 动作 | 最坏结果 | 兜底 |
|---|---|---|
| 改 ESP 引导（只有 `-Mode Install` 会） | 写坏启动顺序 → 开机不进系统 | BIOS 把启动项切回 `Windows Boot Manager`（本包默认不碰 `bootx64.efi`，所以这条路一直在）；`-Mode Uninstall -Yes` 删启动项，覆盖过 `bootx64.efi` 时才还原它（备份 `.40hx.bak` 在 ESP） |
| 恢复 ACE-BOOT（开机任务/`ACE修复 /fix`） | 卡进系统界面 / 登录后无桌面 | 跑 `工具-测试与修复\桌面恢复.cmd`（无桌面也能跑）；再不行 `sc config ACE-BOOT start= disabled` + `taskkill /IM ACE-Tray.exe /F`，之后在游戏客户端点"修复 ACE" |
| 改目录 ACL（`-Mode Repair` 的安全加固） | 极端情况下目录里的文件读不了 | 双击 `工具-测试与修复\回滚-安全加固.cmd`（优先，它只动这 4 个已知目录且用备份恢复）；手工恢复继承用 `icacls "C:\ProgramData\CMP40HXGen2" /inheritance:e /T /C`（**注意**：这等于放弃这层加固） |

**注意**：本包**从不**复位显卡（`Gen2AutoHard=0`/`Gen2PnpFallback=0`）、**从不**删除客户的数据文件、
**从不**改别的软件（如七彩虹 iGame Center）的服务与配置。
