# 排查指引（装到别的电脑上报错时看这里）

> 适用：`Install-40HXUnlock.ps1` / `一键安装.cmd` 这套包。原则——**先取证，再动手**。
> 本文件按“报错关键字”组织，`Ctrl+F` 搜你日志里的原话即可跳转。

---

## 0. 30 秒流程

1. **看退出码**（本文件第 1 节有表）。脚本失败时会自己打印一个「出错怎么办」区块，里面已经把下面这几个路径写好了。
2. 完整日志在 `本包目录\logs\run-<日期>-<时间>-<模式>.log`（每次运行一个文件，失败就贴这个）。
3. 只体检、不改动：`powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Check`
4. 想退回去：`... -Mode Uninstall -Yes`（然后重启一次）

三条命令都能直接用：本包目录里 `Shift+右键 → 在此处打开 PowerShell 窗口`，或者用 `一键安装.cmd` 同款提权方式。

---

## 1. 退出码表

| 退出码 | 含义 | 先查 |
|---|---|---|
| 0 | 全部成功（可能有 `[提示]`，不影响功能） | —— |
| 1 | 有步骤失败 | 日志里的 `[失败]` 行 |
| 2 | 前提不满足 / 不是管理员 | 第 3 节、第 6 节 |
| 3 | 载荷缺失或被改动（sha256 对不上） | 第 2 节（杀软删过 / 没拷全） |
| 4 | 固件变量(NVRAM)读写失败 | 第 4 节 |
| 5 | 驱动或服务失败 | 第 5 节 |

`-Mode Check` 的退出码同样遵循这张表（Check 用 2 表示前提有问题，用 1 表示现状有失败项）。

## 2. 杀软（**最常见，先看这节**）

### 2.1 火绒弹「Exploit/Vulndriver.ad」——这是**预期**的

典型提示原文：

```
病毒名称：Exploit/Vulndriver.ad
病毒路径：C:\Windows\System32\drivers\ThrottleStop.sys      ← 或 %ProgramData%\...\ThrottleStop.sys
操作类型：修改
操作结果：已处理，删除文件
操作进程：C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
操作进程命令行：... -File ...\Install-40HXUnlock.ps1 -Mode Install
```

原因：`ThrottleStop.sys` 是 **BYOVD**（自带易受攻击驱动）类型的内核驱动，PCIe Gen2 那条路只能靠它，所有同类方案都会被报毒。不是包坏了、不是中毒。

**要做的事**：在火绒里把它放进信任区（**必须做，否则每次开机自愈会反复触发**）：

```
火绒安全 → 主界面右上「≡ / 安全设置」→「信任区」→ 添加：
  文件：C:\Windows\System32\drivers\ThrottleStop.sys
  文件：C:\Windows\System32\drivers\WinRing0x64.sys
  文件：C:\Windows\System32\drivers\inpoutx64.sys
  目录：C:\ProgramData\CMP40HXGen2
  目录：本包目录（例如 D:\40hx-unlock\40hx-oneclick）
```

如果安装时它已经删了文件：**不用重装**。脚本在开机任务里有 **多源自愈**（`C:\ProgramData\CMP40HXGen2\drivers`、`C:\ProgramData\40HXUnlock\drivers`，再加 ESP 分区 `\EFI\40HX\drv` 兜底——杀软不扫 EFI 分区）；首选路径要用的 `inpoutx64.sys/.dll` 由重训工具自己在每次开机时从上面那两个 `%ProgramData%` 目录补回。加完信任区后跑一次：

```
powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Repair
```

### 2.2 其它杀软

- **Windows Defender**：一般只隔离不解压出来的东西；若被拦，加排除项：`设置 → 病毒和威胁防护 → 排除项`，加 `C:\ProgramData\CMP40HXGen2` 与三个 `.sys`（ThrottleStop / WinRing0x64 / inpoutx64）全路径。
- **360 / 电脑管家**：除了文件信任，还要关掉它们的**「启动项保护 / UEFI 保护 / 引导区保护」**，否则第 4 节的固件变量写不进去（症状：退出码 4，`无法获得固件变量读写权限` 或 `写 Boot000x 失败`）。
- **联想/华硕自带的安全组件**（Lenovo Vantage、ASUS Armoury Crate 的启动项锁）同理。

### 2.3 腾讯 ACE-BOOT 拦驱动（游戏玩家机器常见）

**先说现在的默认行为（2026-09-29 起）**：开机任务首选 `40hx-retrain-inpout.ps1` —— 它用 `inpoutx64.sys` 直接 MMIO 写 GPU 寄存器，
**全程不停 ACE-BOOT**。所以正常机器上：

```
%ProgramData%\CMP40HXGen2\windows\logs\postbind.log  末尾应看到
  ---- NewPath start: ... -Apply ...
  ---- NewPath EXIT=0 ...
  PASS: Gen2 reached on the new path - ACE-BOOT was never stopped
```

这一段里**不该出现** `ACE-BOOT 已停止 / 已恢复运行` 这类行 —— 出现了说明走的是下面那条老路径。
逐条硬件读数在同目录 `retrain-inpout.log`（`pre:` / `writeOk=True readback=` / `GPU final: Gen2 x16 LNKSTA=0x1102` / `ROOT final: 0xF102`）。

只有新路径 **退出码非 0** 时才回落老路径（postbind.log 里会有 `NewPath did not PASS - exit=n - falling back to the legacy ACE path`），
那时才需要在运行的那十几秒里「停 ACE → 落地 Gen2 → 恢复 ACE」（必要时先结束托盘进程，因为托盘会把它卡在 STOP_PENDING）。**两种情况下都不需要手动禁用反作弊**。

新路径失败时按 `NewPath EXIT=n` 对号入座（工具自己的退出码，不是安装脚本的退出码）：

| n | 含义 | 先查 |
|---|---|---|
| 13 | `inpoutx64` 驱动没起来 | 多半是杀软隔离了 `inpoutx64.sys` → 加信任区 + `-Mode Repair`；或 `sc query inpoutx64T` 看服务状态 |
| 11 | 基线不认识 / 找不到 PCIe cap | 被别的工具改过寄存器或固件不是本方案写的（重跑一次 `Install` 写回 ESP 固件） |
| 12 | 120 秒内 GPU 没就绪 | 显卡驱动没起来 / 卡被复位过（Code 43）→ 冷启动 |
| 10 | 链路没到 Gen2 | 主板重训行为不同（少见）→ 仍走老路径，能落地就行 |
| 3 | `WinRing0` 不可用 | 服务/驱动缺失 → `-Mode Repair` |

老路径的症状（只在新路径失败时才需要看）：**算力是好的**（`40hx_log.txt` 有 `UNLOCKED`），但 `C:\ProgramData\CMP40HXGen2\windows\logs\last.log` 里是
`[SC] StartService 失败 31` / `FATAL: ThrottleStop service did not start`，开机任务 rc=30；同时开机弹「检测到与游戏可能存在兼容问题的软件程序加载: ...ThrottleStop.sys」。
这不是故障，老路径自己会处理：只要 `last.log` 里最终是 `PASS` + `EXIT=0` 就算成功。反过来，如果某次开机 ACE 恢复得比任务早，下一轮会重试，最多 3 轮。

**换安装目录 / 服务改名也照样处理**（这是有意的设计）：`ACE-Toggle.ps1` 不认死路径也不认死名字 ——
它找的是「正在运行 且 驱动 ImagePath 含 `AntiCheatExpert`」的驱动（没有才回退按名字 `ACE-BOOT` 找），托盘进程按可执行文件完整路径找（找不到才回退按映像名 `ACE-Tray.exe`）。
停止前会把**原始启动类型**记到 `logs\ace-state.json`，恢复时按记录还原，不会硬把启动类型改成 `system`。

怎么确认「就是 ACE 拦的」：
- `%ProgramData%\CMP40HXGen2\windows\logs\postbind.log` 里该次开机有 `StartService 失败 31` / `FAIL: post-bind step did not reach Gen2` / `EXIT=30`；
- 同时 `C:\Program Files\AntiCheatExpert\`（或你机器上的实际安装目录）里会多出一个 `ace-boot-<时间戳>.log`，时间戳就是那次拦截 —— 文件本身是加密/二进制的，看时间对不对得上即可，不用读内容；
- 算力不受影响：`40hx_log.txt` 该次开机仍有 `*** UNLOCKED ***`。

如果日志里出现 `ACE WARN: 检测到其它厂商反作弊正在运行…: vgk / EasyAntiCheat / BEDaisy …`，说明机器上还有**非腾讯**的反作弊在跑，
本脚本故意不碰它们。这种情况下若 Gen2 一直落地不了，只能人工确认放行 `ThrottleStop.sys`（或临时退出该反作弊）后再跑一次 `-Mode Repair` + 一次重启。
若日志出现 `ACE WARN: … 仍未停止 —— 本次重训很可能 EXIT=30`，说明该次没停成功（比如托盘是别的进程名、或被策略保护），下次开机会自动重试；
连续多次都这样，按上面 `-Mode Repair` 后手工确认一次。

## 3. 前提不满足（退出码 2）

| 日志原话 | 处理 |
|---|---|
| `固件不是 UEFI 模式` / `固件类型 : Bios —— 必须是 UEFI` | BIOS 里关 **CSM**、开 UEFI 引导；老盘是 MBR 还要 `mbr2gpt /convert /allowFullOS` |
| `系统盘不是 GPT` | 同上，MBR → GPT |
| `Secure Boot 开着` | BIOS → Security → Secure Boot → **Disabled**（本方案用的是未签名 EFI，必须关） |
| `BitLocker 开着（会索要恢复密钥）` | `manage-bde -status` → `manage-bde -protectors -disable C: -rebootcount 0`；或先在设置里暂停保护 |
| `没找到 CMP 40HX (DEV_1F0B)` | ①卡插紧、供电（6pin）到位；②装 NVIDIA 驱动；③有的机器要在 BIOS 里把 PCIe 槽设为 Gen1/自动并开 **Above 4G Decoding**；④设备管理器里看有没有带感叹号的未知设备 |
| `这个模式需要管理员权限` | 双击 `一键安装.cmd`（它自己弹 UAC）；**不要**直接右键 `.ps1` 运行（那样不提权） |

BIOS 里还建议（第 5 节“开机没解锁”也靠它）：

- **Above 4G Decoding = Enabled**（这是 40HX 类矿卡最常见的失败原因）
- **Fast Boot = Disabled**、**CSM = Disabled**
- PCIe 槽速度先设 `Auto`（解锁后才谈 Gen2）

## 4. ESP 与固件启动项（退出码 4 / 3）

| 日志原话 | 原因与处理 |
|---|---|
| `ESP 挂载失败（需要管理员；或 ESP 被 BitLocker/其他工具占用） ; mountvol 报: ...` | ①确认是管理员窗口；②手动 `mountvol` 看盘符占用（本脚本会先找已经挂载出来的 ESP，再找空盘符挂）；③BitLocker 开着挂不上；④**虚拟机/WSL 里跑不了**，要在真机跑；⑤第三方的分区工具占着 ESP，关掉再试 |
| `无法获得固件变量读写权限` / `写 Boot000x 失败` | ①管理员；②关掉安全软件的「启动项/UEFI 保护」（见 2.2）；③极少数老主板不支持写固件变量 → 走 BIOS 手设（见下） |
| `回读 Boot000x 失败` / `回读内容与写入不一致` | 个别主板对某些 `Boot####` 槽位处理异常。重跑一次；还不行就**进 BIOS 手动选启动项**（脚本已把解锁固件写到 `\EFI\Boot\bootx64.efi` 兜底，多数主板不看 NVRAM 也能生效）。备份的原始字节在同一次运行的 `backup\<时间戳>\` 下 |
| `没有空闲 Boot#### 槽位` | NVRAM 满（少见）：进 BIOS 启动项里删几个没用的 |
| `BootOrder 写入失败` | 同上；或直接进 BIOS 把「40HX Unlock」排到第一位（启动项已经建好了，只差排序） |
| 装完**开机不进** `40HX Unlock`，但 Windows 能正常进 | 这是主板的固件启动项排序被别的系统改写（Windows 更新、双系统、PE 工具都会干这事）。三种办法：①重跑 `-Mode MakeDefault`；②进 BIOS 启动项手动选一次；③就用 `\EFI\Boot\bootx64.efi` 兜底（安装时已写入，BBS 里把硬盘设为第一启动项即可） |
| 想临时试一次、不落盘 | 加 `-BootMode next`，只设 `BootNext`（跑一次自动恢复，最安全） |

**验证启动项是否真的写进去了**（不重启也能看）：

```
bcdedit /enum firmware          :: 应能看到 description 带 40HX Unlock 的条目
powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Check
```

`-Mode SelfTest` 会做无损自检：ESP 读写往返、NVRAM 写入→逐字节回读→删除、BootOrder 原样写回，用临时槽位，不碰你正在用的项。

## 5. 装完完全关机再开机后“没效果”（退出码 0 但结果不对）

先分清是**算力**没解锁还是 **Gen2** 没落地，判据完全不同：

| 现象 | 判据在哪 | 说明 |
|---|---|---|
| 算力没解锁 | ESP 根目录 `40hx_log.txt` 有没有 `*** UNLOCKED (SS0=0x88888888 SS1=0x8) ***`，看它的时间戳是不是**本次开机** | 没有这一行 / 时间是上次开机的 → **EFI 没被执行**（去第 4 节“开机不进 40HX Unlock”） |
| Gen2 没落地 | 先看 `%ProgramData%\CMP40HXGen2\windows\logs\postbind.log` 末尾：`PASS: Gen2 reached on the new path` = 新路径成功（ACE-BOOT 没被停）；若出现 `falling back to the legacy ACE path`，同段的 `NewPath EXIT=n` 就是新路径失败的原因（见 2.3 的表），再看老路径 `logs\last.log` 末尾要有 `PASS:` 与 `EXIT=0`；有 `GUARD=PASS SS0=0x88888888` 说明守卫通过 | 老路径 `EXIT=0` 但 `already physical Gen2 x16` 也算成功（已经是 Gen2，无需再写） |
| 两个都看着像坏的 | `-Mode Verify` 一次看结论 | 结论行会写「算力解锁 PASS/FAIL + PCIe Gen2 PASS/FAIL」 |

### 5.1 GSP 没开 → 代码 43 / 黑屏（2026-09-30 新增，客户机高发）

**症状**：装完提示全部成功 → 重启/开机后**黑屏 1~2 分钟**才进系统 → 设备管理器里 `CMP 40HX` 是**黄色感叹号（代码 43）**。

**判据（一条就够）**：看 `nvidia-smi -q` 里的 GSP 行

- 显示**版本号**（如 `615.71.08`）＝ GSP 已启用（正常）
- 显示 `N/A` ＝ **GSP 没开** ← 就是它。解锁固件把算力解开后，没有 GSP 的 `nvlddmkm` 认不了这张卡 → 黑屏一段时间 + 代码 43
- 没有这一行 / 找不到 `nvidia-smi.exe` ＝ 驱动没装好，先装驱动再谈解锁

**修（两条一起做）**：

1. 确认开关在**正确位置**（Windows 上写这里才生效；实测 `Services\nvlddmkm\Parameters` 里 0 匹配）：
   `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}\<000X>` 的
   `EnableGpuFirmware = 1`（DWORD）—— 取 `MatchingDeviceId` 含 `ven_10de&dev_1f0b` 的那个子键。
   2026-09-30 起的 `-Mode Repair` 会自动写对位置（日志出现 `GSP 开关已写: 显示类子键 0001 ... <无> -> 1`）。
2. **完全关机**（开始菜单 → 关机，最好拔电 10 秒）再开机，然后 `-Mode Verify` 复核：
   结论必须是 `GSP 固件 : PASS (版本号)` + `40HX 设备 : OK（没有代码 43）`。

> 旧包（2026-09-29 及以前）有两个坑会让 GSP 永远开不起来，别再用旧包：
> ① 把 `nvidia-smi` 里的 `N/A` 当成“已开启”；② 把开关写在 `Services\nvlddmkm\Parameters`（驱动不读那里）。
> 只读取证 + 一键修复见 `诊断包-20260930/`（`一键诊断.cmd` / `修复-GSP.cmd`）。

**情况 B：开关本来就是 1，但 GSP 还是 `N/A`（2026-09-30 客户机实遇）**

日志会写：`GSP 开关已写: 显示类子键 0002 [...] EnableGpuFirmware 1 -> 1`（写之前就已经是 1）。这说明**不是开关的问题，是驱动从来没在开机时重新初始化过**：

| 原因（按概率） | 判据 | 处理 |
|---|---|---|
| **快速启动开着**（"关机"=混合关机，内核/nvlddmkm 从 hiberfile 恢复） | `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power` 的 `HiberbootEnabled = 1`（诊断报告第 1 节也会打） | `-Mode Repair`（会自动写 0），或 控制面板→电源选项→选择电源按钮的功能→更改当前不可用的设置→取消"启用快速启动"；然后**完全关机**再开机 |
| 装完驱动后一直没真正冷启动过 | 上次开机时间早于驱动安装时间 | 完全关机（不是重启）再开机 |
| 驱动包被裁剪，缺 GSP 固件 | 诊断报告第 4 节"驱动库里的 GSP 固件文件"里没有 `gsp_tu10x.bin` | 换官方完整驱动包重装，再冷启动 |
| 开关写在了非权威子键 | 诊断报告第 0 节"权威显示类子键"（`Enum\<实例>\Driver`）与写入的子键号不一致 | 2026-09-30 起 `-Mode Repair` 会按权威子键写；把报告发回来核对 |

处理完仍 `N/A`：跑 `诊断包-20260930\一键诊断.cmd`，把报告发回来（报告里 GSP 行、权威子键、快速启动、GSP 固件文件都在第 0/1/4 节）。

注意两个**假警报**：

- `nvidia-smi` 的 `pcie.link.gen.current` **不可信**：空闲省电或纯计算负载时可能一直显示 1，即使实际已经是 Gen2。看 Gen2 用新路径的 `retrain-inpout.log`（`GPU final: Gen2 x16 LNKSTA=0x1102` / `ROOT final: Gen2 x16 LNKSTA=0xF102`）、老路径的 `last.log` 的 `GPU final: Gen2 x16`，或 `状态自检.bat` 的实测带宽（Gen2 约 5.7~6.2 GB/s，Gen1 只有 3.2~4）。
- 关机前读出来的 `SS0=0` / `0xFFFFFFFF` 是假读数（驱动用完即卸，本来就读不到）。以开机的 `40hx_log.txt` 为准。

若某次开机 Gen2 没落地：等 1~2 分钟看任务重试的结果，或手动跑
`schtasks /run /tn "CMP40HXGen2 PostBind"` → 再看 `postbind.log` 末尾（新路径的 `PASS` 行或 `NewPath EXIT=n`）和老路径的 `last.log`。
仍失败就 `-Mode Repair` 补齐驱动/服务（驱动的缺失 90% 是杀软干的，见第 2 节）。

## 6. 驱动 / 服务相关（退出码 5）

| 日志原话 | 处理 |
|---|---|
| `[SC] OpenService 失败 1060` / `服务不存在` | 服务被删了。跑 `-Mode Repair`（会 `sc create` 重建 + 重新拷驱动） |
| `[SC] StartService 失败 31` | 被 ACE-BOOT 拦 → 见 2.3，属自动处理范围 |
| `ThrottleStop service did not start` / `cannot open \\.\ThrottleStop` | 驱动文件不在了（杀软）或没起来 → 加信任区 + `-Mode Repair` |
| `驱动被删: C:\Windows\System32\drivers\ThrottleStop.sys —— 杀软隔离，请把它加入信任区后重跑 Install` | 脚本已经检出杀软清场，按提示加信任区后 `-Mode Repair` |
| 显卡变 **Code 43 / 感叹号 / 黑屏** | **先按 5.1 查 GSP**（未启用 = 必然 43）；GSP 正常才考虑“被复位过”这条（本包默认不写 `Gen2AutoHard/Gen2PnpFallback` 的开启值，正常不会触发）。不论哪种，都**必须完全关机（冷启动）**，热重启没用 |
| `WinRing0_1_2_0` 是 `STOP_PENDING` / 老路径 `EXIT=31`（`WinRing0_1_2_0 service did not start`） | 上次 stop 没收尾（进程被强杀/驱动文件被删）→ 服务卡在"正在停止"。2026-09-30 起新路径工具会**先等它落定（45 秒）再重试启动 3 次**，并在收尾时先关掉自己的设备句柄再 stop（`cleanup: closed WinRing0 handle` → `STOPPED`）；老路径的 `:heal` 会补回缺失的 `.sys` 与 `sc create`。仍不行就重启一次（SCM 状态不跨重启） |
| `>>> inpoutx64T did not reach RUNNING` / `NewPath EXIT=13` | 新路径的 MMIO 驱动没起来：`inpoutx64.sys` 被杀软隔离，或服务创建被拦 → 加信任区 + `-Mode Repair`。（`sc query inpoutx64T` 平时查不到 / 是 STOPPED 属正常：工具用完就 stop+delete） |
| `新路径驱动被删: ...inpoutx64.sys —— 杀软隔离` | 安装脚本 10 秒观察期就检出杀软清场 → 加信任区后 `-Mode Repair` |
| `baseline is not a known state - refusing to write` / `NewPath EXIT=11` | 寄存器基线不是本方案认识的值（别的工具改过，或 ESP 上的固件不是本方案的）→ 重跑 `-Mode Install` 写回固件；工具**故意拒写**，不会瞎写坏现场 |
| `pre: GPU LNKSTA=0x1101 Gen1` 但结尾仍是 `Gen1` / `NewPath EXIT=10` | 这台主板的重训行为不同（少见）→ 走老路径也能落地，只要 `last.log` 是 PASS 即可；两边都不行再来找我 |

## 7. 换到别的电脑时的差异

- **没有 Python**：`状态自检.bat` 要 `C:\Windows\py.exe` 才能实测带宽/算力；没有就用 `-Mode Verify`（纯 PowerShell，不依赖 Python）。
- **没装 NVIDIA 驱动**：先装官方驱动（CMP 40HX 用普通 GeForce 驱动即可），否则 `-Mode Check` 会报找不到 `DEV_1F0B`。
- **多显卡**：脚本只认 `VEN_10DE&DEV_1F0B`，其它卡不受影响；但 BIOS 的 Above 4G 必须开。
- **CPU 平台不同**：本包在两全路径上依赖主板的 PCIe 重训行为，实测平台见 `README-使用说明.md` 第 7 节；换 AMD 平台/笔记本独显直连的结果可能不同，先跑 `-Mode Check` + `-Mode SelfTest` 再装。
- **企业/网吧机器**：可能有 BIOS 写保护、设备安装限制策略（`DeviceInstall` 策略会让驱动装不上）→ 先确认 `sc create` 不被拦。

### 7.1 显卡不在第一个槽 / AGESA 高总线主板（2026-09-30 起自动处理）

`40hx-retrain-inpout.ps1` 以前写死 `01:00.0`（显卡）与 `00:01.0`（根端口）。显卡插在第二个槽、插在桥后、或
AGESA 高总线主板（厂商文档实测微星 B450 显卡在 bus 0x10）上，旧版会**每次开机白等 120 秒**然后 `NewPath EXIT=12`
回落到旧路径。现在改成自动探测，日志里能看到：

```
  detect: gpu=0x0100  root=0x0008  src=PnP
  GPU candidate 0x0100 -> id=0x1F0B10DE
  ROOT candidate 0x0008 -> id=0x4C018086  class=0x060400
  using GPU=0x0100  ROOT=0x0008
```

探测不到就**拒写**并 `exit 11`（不会拿错位置去写寄存器）；要手工指定可用
`-GpuBdf 0x0200 -RootBdf 0x000a`（十六进制）。

## 8. 报错时请带上这些信息（贴给我最快）

## 9. 回滚（任何时候都能干净退回）

```
powershell -ExecutionPolicy Bypass -File "<包>\Install-40HXUnlock.ps1" -Mode Uninstall -Yes
```

会做：还原 `\EFI\Boot\bootx64.efi` 备份 → 删 `\EFI\40HX` → 删固件启动项并从 BootOrder 移除 → 删开机任务与厂商残留任务 → 删服务与驱动副本 → 清状态文件。
**卸载后要重启一次**，解锁才会真正消失（解锁是每次开机由 EFI 写寄存器实现的）。

回滚素材在 `backup\<时间戳>\`：`bootx64.efi.40hx.bak`、各 `Boot####` 原始字节、`BootOrder` 原始值、`installed.json`（记录了本次安装用了哪个设备路径）。
