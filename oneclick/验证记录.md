## 自检（SelfTest）四段明细

1. **权限**：`SeSystemEnvironmentPrivilege` 启用 OK。
2. **ESP 读写往返**：写入 4KB 随机数据 → 回读一致 → 删除成功；ESP 上两处固件哈希 = `1e9ca43fab3d5ce8…`（OnlyEFI v0.1.1）。
3. **NVRAM 往返**：按现场 ESP 分区构造 42 字节设备路径节点，与固件里**正在使用**的启动项节点（`Boot0003`/`Boot0005`）**逐字节一致**；
   写入临时项 → 逐字节回读一致 → 解析出 `描述/路径` 正确 → 删除 → 确认消失。
4. **BootOrder**：原样写回 + 回读逐字节一致，且写完仍是 `0005,0003,0002`；`BootNext` 为空。

## 过程中发现并修掉的真问题（都是会“静默失败”的那种）

1. **设备路径节点末尾 2 字节不是保留位**：HardDrive 节点 42B = 4B 头 + 4B 分区号 + 8B 起始 LBA + 8B 扇区数 + 16B 分区 GUID + **1B MBRType(0x02=GPT) + 1B SignatureType(0x02=GUID)**。
   第一版写成 `00-00`，自检立刻报“与现场节点不完全一致”；改成 `02-02` 后与固件在用的节点逐字节一致。**抄模板/想当然都会踩这个坑。**
2. **不能抄现成启动项做模板**：本机 NVRAM 里名为 "Windows Boot Manager" 的两条是过期项（GUID `e775e299-…` ≠ 现场 ESP `3f0ea28b-…`，甚至没有 FilePath 节点）。
   现在改为 **从现场 ESP 分区（`Get-Partition` 的 GPT GUID/起始/大小/分区号）构造节点**，并用“与现场启动项逐字节比对”自证。
3. **幂等路径的 PASS 文案不同**：helper 已到 Gen2 时输出 `PASS: already physical Gen2 x16; no writes needed.`，
   只匹配 `PASS: physical Gen2 x16` 会把正常状态误判为 FAIL（第一版 Verify 就误判了）。已改成正则 `PASS:\s*(already\s+)?physical Gen2 x16`，
   同族写法在 `coldboot-report.ps1` 里也一并修掉。
4. **ESP 已挂在别的盘符时 `mountvol <新字母>: /S` 直接报“参数错误”**：现在先扫现有盘符找已挂载的 ESP（判据 `\EFI\Boot` 或 `\EFI\Microsoft`），再尝试新挂载。
   （曾因此让一次安装停在“ESP 挂载失败”。）
5. **`.cmd` 编码不能想当然**：上游 `RunPostBind.cmd` 是 UTF-8，被当 GBK 读回写会把中文注释改坏。现在按 BOM/严格 UTF-8/GBK 自动识别并**原编码写回**。
6. **CRLF + `(?m)$`**：用 `^for %%S in \(.*\) do \($` 替换驱动源行永远匹配不上（`$` 停在 `\n` 前，`\r` 还在），改用 `(?=(\r?$))` lookahead 后正常。
7. **别把裸 `.sys` 拷进包目录/`C:\Temp`**：火绒实测报 `Exploit/Vulndriver.ad` 并秒删（用户已收到弹窗）。
   现在裸驱动只写 `System32\drivers` 与两个 `%ProgramData%` 目录（实测 10 秒后仍在），载荷里是 base64 文本，另有 ESP 兜底源。

## ACE-BOOT 处理的加固与实测（2026-09-28 晚，针对「ACE 装到别的目录」）

原来只按服务名 `ACE-BOOT` 操作、并按 `taskkill /IM ACE-Tray.exe` 找托盘，恢复时写死 `start= system`。现在改成 `payload\windows\ACE-Toggle.ps1`：

| 真机端到端（`-Mode Install -RunNow`） | 开机任务里走新流程 | `postbind.log` 出现 `ACE INFO: ACE-BOOT 正在运行…已停止` → `PASS: physical Gen2 post-bind step succeeded` → `已恢复原始启动类型 / 已恢复运行`；`last.log` = `PASS: already physical Gen2 x16` + `EXIT=0`；事后 ACE-BOOT = RUNNING / SYSTEM_START ✓ |

过程中修掉一个真问题：`RunPostBind.cmd` 调用 PS 脚本时自己持有 `postbind.log` 的 `>>` 句柄，脚本再 `Add-Content` 同一文件 → 报「文件正由另一进程使用」（实测 19:34 那次日志里就是这堆报错）。
现在脚本写日志失败会自动回退到标准输出，由 cmd 的 `>>` 落盘；调用处也不再传 `-Log`。19:38 那次运行日志干净、无报错。

## 用户提示的完善（2026-09-28 晚）

做完活之后必须让用户知道“现在该干什么”，这次补齐了三处：

1. **脚本结尾的强制重启提示**（原来只有一行“1) 重启电脑…”夹在列表里）——现在是整块醒目区块：
   `★ 现 在 请 重 启 电 脑 （必须）` + 为什么必须重启 + 重启后第一次开机会慢几秒的预期 + 三种确认方式（状态自检.bat / `-Mode Verify` / ESP `40hx_log.txt` 时间戳）。
2. **本次待办清单（ActionItems）**：运行过程中凡是需要“人”去做的（杀软隔离、GSP 刚被打开、ESP 兜底源没部署、RunPostBind 源行没重写、Secure Boot 读不到、开机任务 rc≠0、日志里有 `ACE WARN`…）
   都会收集起来，在结尾用红字再列一遍，`一键安装.cmd` 也会提示“上面若列了待处理事项，请先处理再重启”。没有待办时明确说“没有需要你额外处理的事项”。
   实测：本机装了火绒 → 结尾列出「火绒/其它杀软：把 README 第 1.1 节的 4 项加进信任区…」。
3. **`下一步-重启后看这里.txt`**：写进包目录（UTF-8+BOM），内容含必须重启、三种确认方式、待办清单、本次结果与日志路径、排查指引路径、回滚命令 ——
   控制台关掉/重启之后还能照着做。实测内容见 `logs` 同级目录，文件名就是它。

另外 `一键安装.cmd` 结尾也改成方框提示：`现在请重启电脑（必须）… 重启后双击 状态自检.bat 看结论；出问题看 排查指引.md`。

## 未在本机执行的部分（如实说明）

- `-Mode Uninstall` 没有在本机实跑：它会拆掉当前可用的解锁状态。其涉及的固件变量**删除**、BootOrder **移除某项**、BootOrder **写回**等动作已由 SelfTest 与探针覆盖
  （写入 → 逐字节回读 → 删除 → 计数回落 → BootOrder/Boot0005 未变），但“卸载后重启回到原生状态”这一步没有做端到端实测。
- 重启验证：本次会话没有重启（重启会中断当前工作）。**每次开机自动解锁**这条链路在本机历史上已多次验证
  （本机 `40hx_log.txt` 与 `last.log` 都是今天这次开机自动跑出来的：EFI 18:34:10 写入解锁，开机任务 18:34:45 落地 Gen2）。
  装完之后第一次重启，请跑 `-Mode Verify` 复核。
