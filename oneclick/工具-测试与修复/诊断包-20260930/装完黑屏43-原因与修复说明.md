# 40HX 一键包 —— 客户反馈"装完重启黑屏 1~2 分钟 + 设备管理器代码 43" 代码审计

审计对象：``（Install-40HXUnlock.ps1 ÷ payload\）
审计日期：2026-09-30　　审计机：技嘉 B560M AORUS ELITE + CMP 40HX（DEV_1F0B / VBIOS 90.06.67.00.04）
结论口径：**能解释"43"的第一顺位是 GSP 没开**（两个代码缺陷叠加，客户机上必然命中）；
　　"黑屏 1~2 分钟"另有两条链路（写死 BDF 的 120 秒等待、固件/引导项指向不对的 ESP），都在下面列了判据。

---

## 一、第一顺位原因：GSP 没开（解锁后驱动认不了卡 = 代码 43）

### 缺陷 A1：把 nvidia-smi 的 "N/A" 当成"GSP 已开启"（Install-40HXUnlock.ps1:1013，Check 同款在 543/576）

```powershell
# Install-Gsp（1011-1018）
$q = (Invoke-Native { & $smi -q 2>&1 } | Out-String)
if ($q -match 'GSP Firmware Version\s*:\s*(\S+)') { Ok ('GSP 已开启 (' + $Matches[1] + ')'); return }   # ← 这里
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\nvlddmkm\Parameters' -Name 'EnableGpuFirmware' ...
```

- NVIDIA 官方文档（GSP Firmware 章节，510/525/560/595 各版本一致）：
  "It will display a valid version if GSP firmware is enabled, or **N/A if disabled**"。
- 也就是说 GSP 关闭时 `nvidia-smi -q` 输出的是 `GSP Firmware Version : N/A` —— **正则照样命中**，
  `$Matches[1]` = `N/A`，脚本认定"GSP 已开启"并 `return`，**从此不再写 EnableGpuFirmware**。
- 同一处逻辑在 `-Mode Check` 里会打出这种自相矛盾的绿字（客户看到的就是"全绿"）：
  `[OK] GSP 固件 : N/A（必须开启，未开则解锁后会 Code 43）`

### 缺陷 A2：就算写了，位置也是错的（1014-1016 行）

脚本写 `HKLM\SYSTEM\CurrentControlSet\Services\nvlddmkm\Parameters`。
本机（一切正常的参考机）实测：

```
HKLM\SYSTEM\CurrentControlSet\Services\nvlddmkm  整棵树搜 EnableGpuFirmware → 找到 0 匹配   ← 脚本写的位置根本没这项
HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}\0001
        DriverDesc="NVIDIA CMP 40HX (RainCandy Technology)"  EnableGpuFirmware=1   ← 真正生效的位置
```

Windows 上开 GSP 的通行做法就是写**显示类子键**（Reddit r/nvidia、guru3D 及多方资料一致：
`[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-...}\0000] "EnableGpuFirmware"=dword:00000001`）。

### 后果链（和客户描述逐字对得上）

1. 安装时报"步骤全部成功"（GSP 被 A1 误判为 OK）；
2. 重启 → 解锁固件写 SS0=0x88888888（算力确实解锁了）；
3. **没有 GSP 的 nvlddmkm 认不了这张被解锁的卡** → 驱动初始化反复重试/超时 → 这段时间**屏幕是黑的（1~2 分钟）**；
4. Windows 最终放弃这个设备 → 回落到基本显示驱动 → 桌面出来了，设备管理器里 40HX = **代码 43**。
5. 厂商 README §5.2 自己就写着：`code43 / 掉驱动 | 解锁未成功、GSP 未启用或状态残留`；
   我们自己的记录里也早有"GSP 必须开，否则解锁后 nvlddmkm 不认 → Code43/黑屏"。

### 为什么客户机上一定命中、而本机没暴露

本机 GSP 是早先**手工**打开的（值在显示类子键 `\0001`），所以一键包从没走过"GSP 未开启"分支——
A1/A2 两个缺陷在本机属于"哑弹"，一到干净机器就炸。属于典型的"开发机绿灯、客户机红灯"。

## 二、第二顺位：retrain 脚本写死了显卡/根端口位置（换机器就失效，还白等 120 秒）

`payload\windows\40hx-retrain-inpout.ps1`

```powershell
$GPU=[uint32]0x0100     # = 01:00.0
$ROOT=[uint32]0x0008    # = 00:01.0
...
for($w=1; $w -le 24; $w++){ ... Start-Sleep -Seconds 5 }   # 等不到就 120 秒后 exit 12
```

- 厂商 README §9 明确：某些主板（AGESA / 高总线，**实测微星 B450 显卡在 bus 0x10**）显卡根本不在 01:00.0；
  多卡 / 非主槽也会变。这种机器上：新路径工具**必然等满 120 秒 → exit 12** → `RunPostBind.cmd` 回落到旧路径
  （停 ACE-BOOT + 杀 ACE-Tray + AutoRetrain，失败还重试 3 轮、每轮隔 15 秒）。
  每次开机白等 2 分钟以上——**与"黑屏一两分钟"的时间尺度吻合**。
- `$ROOT` 只按写死值取，**不校验它是不是 40HX 的父根端口**。若显卡在 01:00.0 而根端口不是 00:01.0，
  脚本会对**错误的链路**做 Retrain（Gen2 落不了地；极端情况下影响那条链路上的设备）。
- 修法：从 Windows 侧自动解析——显卡 BDF 用 `nvidia-smi --query-gpu=pci.bus_id` 或
  `DEVPKEY_Device_LocationInfo`；根端口用 `DEVPKEY_Device_Parent` 反查（并校验它是 PCIe 根端口）。
  解析不出来就 exit 11 别写，绝不猜。

## 三、第三顺位：交付话术让客户"重启"，而厂商文档要求"完全关机"

- 一键包结尾/`下一步-重启后看这里.txt` 写的是"★ 必须重启电脑"；
- 厂商文档在多个失败分支里写的是 **"完全关机再开一次（不要用『重启』）"**：
  `40HXCheck 显示"算力锁定"` / `残留 TLS 会随显卡复位消失` / 引导异常等；我们自己的记录也有
  "硬回退后 Code 43 热重启无效，必须冷启动"。
- 客户照我们的话做"重启"，本来冷启动能清掉的状态就留在机器上 → 变成 43。
- 修：安装结尾、`下一步-重启后看这里.txt`、README 统一改成
  **"完全关机（开始菜单→关机；最好拔电 10 秒）再开机"**。

## 四、第四顺位：策略键只在"已存在时才写"（干净机器上保护措施没生效）

```powershell
# Install-Task（995-1000）
if (Test-Path 'HKLM:\SOFTWARE\40HXUnlock') {
  foreach ($kv in @(@('Gen2AutoHard', 0), @('Gen2PnpFallback', 0))) { New-ItemProperty ... }
  Ok '策略键 Gen2AutoHard=0 / Gen2PnpFallback=0（绝不复位显卡 = 不毁算力）'
}
```

- `HKLM\SOFTWARE\40HXUnlock` 是**厂商安装器**建的；干净机器上不存在 → 这两个"永不复位显卡"的键**根本没写**。
- 厂商 v3.2 的 Gen2AutoHard 默认是 1：会做 Stage2 回退（Link Disable + PnP disable/enable），
  厂商文档自己说这会让"40HX 是唯一显示卡的机器登录后黑屏几秒"，而**复位显卡会清掉算力并可能留下 Code 43**。
- 一键包只禁用了两个任务名（`40HX PCIe Gen2 Bring-up`、`40HX-Gen2-Retrain`）+ 摘掉 HKCU Run 的 `40HXGen2`；
  厂商工具还有别的自启形态（登录任务/常驻守护/失败重试任务），名字一变就漏。
- 修：无条件建键并写 0；扫全部自启（任务名/动作/命令行含 40HX）逐个禁用并记日志。

## 五、第五顺位：ESP 与引导项可能不是同一个分区（另一种"黑屏一会儿再进系统"）

- `Mount-Esp`（221-241）只按"哪个盘符上有 \EFI\Boot 或 \EFI\Microsoft"挑（优先已被别的工具挂住的盘符）；
- 而 `Install-BootEntry` 里的设备路径节点是用 **Get-EspPartitionInfo（系统盘的 ESP 分区）** 构造的。
- 两者不是同一个分区时：固件里那条 "40HX Unlock" 指向的 ESP 上没有 `\EFI\40HX\40HXUNLK.EFI`
  → 固件找不到文件 → 干等/顺延到下一条 → **黑屏一段时间后进系统**（而且这次解锁没跑）。
- 修：挂到的盘符必须与 `Get-EspPartitionInfo` 的分区 GUID 吻合；不吻合就先卸掉错的那个再挂对的。

## 六、次要问题（顺手一起修）

1. `Install-Gsp` 找不到 nvidia-smi 时只 `Warn` 一句（1011 行）：机器还没装驱动就静默跳过 GSP，
   客户之后才装驱动 → 直接 43。应加进"重启前必须先处理"的待办，并在 `-Mode Verify` 里当失败。
2. `状态自检.bat`（6 步版）**完全没检查 GSP**（本机 grep 无 GSP/43 字样）→ 客户"全绿"也发现不了 43 的根因。
3. `排查指引.md` 第 98/193 行把 Code 43 / exit 12 全部归因于"走了硬回退/显卡被复位"，
   **没有一条指向 GSP 没开** → 售后会绕圈（本次客户就是）。
4. `RunPostBind.cmd` 新路径失败后回落到旧路径时会**停 ACE-BOOT + 杀 ACE-Tray**；
   如果新路径因为写死 BDF 长期失败，等于每次开机都在动反作弊。

## 八、建议的修复顺序（改代码 vs 现场救急）

**现场救急（客户机上就能做，今晚可试）**
1. 跑 `一键诊断.cmd`，把报告发回来；
2. 若 `[判据 A]` = "GSP 未启用" → 跑 `修复-GSP.cmd` → **完全关机**（拔电 10 秒）→ 开机 → 再跑诊断复核；
3. 若判据 A 已经正常，则看 `[判据 B]`（显卡位置）与第 8 节开机时间线，按下面顺序试：
   先**完全关机冷启动**一次（清显卡残留状态），不行再走代码修复。

**代码修复（建议出 v20260930 包，一处一处改，改完按四步验证）**
1. `Install-Gsp` / `Get-CheckReport`：GSP 值必须把 `N/A`（以及缺行）判为"未启用"；写显示类子键
   （遍历 `Control\Class\{4d36e968-...}\####`，取 MatchingDeviceId 含 `ven_10de&dev_1f0b` 的那个，写 DWORD 1），
   同时保留写 nvlddmkm\Parameters（无害）；`-Mode Verify` 里 GSP 未启用 = 失败。
2. `40hx-retrain-inpout.ps1`：BDF/根端口改为自动解析 + 校验父子关系，解析失败 exit 11。
3. 文案：所有"必须重启" → "必须**完全关机**再开机（最好拔电 10 秒）"。
4. `Install-Task`：无条件建 `HKLM\SOFTWARE\40HXUnlock` 并写 0；扫描并禁用全部含 40HX 的自启。
5. `Mount-Esp`：与 `Get-EspPartitionInfo` 分区对齐一致。
6. `状态自检.bat` 加一步 GSP 检查；`排查指引.md` 补 Code 43 的 GSP 分支。

**验证口径（照旧四步，别省）**：①整包拷到干净目录 `-Mode Check`（0 失败 0 提示）
②干净机器（或至少"未开过 GSP"的机器）`-Mode Install` → 冷启动 → `-Mode Verify` 两全

  补丁出包后必须在**一台没开过 GSP 的干净机器**上按第八节的验证口径走一遍。
- 第二种黑屏解释（固件找不到 ESP 上的 EFI、固件链式加载失败）只是代码路径上可能，本机没复现。
